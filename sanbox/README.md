# sanbox/ — מישור-ההתמדה הריבוני (התיקייה-האחת של הגוף)

> הסנדבוקס נמחק ~5 פעמים ביום. **התיקיה הזאת היא הבית הקבוע.**
> כל מה שהגוף (הסוכנים, הרשת, המנוע) צריך כדי לחיות, להתאושש ולהמשיך — **בלי תלות במפעיל** — נכנס מכאן.

## הבהרה (2026-10-09): "יש 2 תיקיות"?
`sanbox/` היא **התיקייה הקנונית והיחידה** של מישור-ההתמדה-המפעיל.
התיקיות `agent/` (חוק+כספת), `sovereign/` (עוגני-שרשרת) ו-`mini-services/` (איברי-הרשת) הן **איברים של אותו גוף — לא שכפולים**. כל-דבר שהמפעיל פותח ידנית → תיקיה-זו.

## תחילת-עבודה ב-60 שניות
```bash
bash sanbox/bootstrap.sh           # חייאה מלאה מהגיט (idempotent, אל-כשל)
bash sanbox/verify.sh              # מטריצת-קבלה — חייב PASS (exit 0)
bash sanbox/commit-loop.sh start   # לולאת-התמדה: קומיט+דחיפה דרך-השער כל 5 דק'
```

**אתר-המפעיל** (מאחורי-סיסמה, loopback): `http://<host>:81/operator?XTransformPort=3046`
- ביקור-ראשון = חלון-אתחול: קובעים סיסמה פעם-אחת (נשמר כ-hash scrypt בלבד, git-ignored).
- סוכנים לא צריכים את האתר — הם עובדים ישירות עם הסקריפטים; ל-HTTP: header `X-Op-Token` מול `state/agent-token`.

## מפת-התיקיה
| קובץ | תפקיד |
|---|---|
| `AGENT_BOOT.md` | פרוטוקול-עלייה לכל סוכן (חובה לפני-פעולה) |
| `SOVEREIGNTY.md` | חוזה-הריבונות: אוטונומיה מלאה מהמפעיל |
| `SECURITY.md` | מודל-איום + חוקי-סודות (כנות מלאה) |
| `MANIFEST.json` | רכיבים/פורטים/בדיקות — קריא-מכונה |
| `bootstrap.sh` | חייאה: גיט→התקנה→צי (3040-3043)→אתר (3046) |
| `verify.sh` | מבחן-קבלה: git/law/chain/fleet/operator/secrets/autonomy/persistence |
| `commit-loop.sh` | לולאת-התמדה: snapshot ניטרלי + `scripts/sovereign-push.sh` |
| `autonomy/` | תור-משימות ומצב-ריבונות (הזיכרון-המשותף של הסוכנים) |
| `operator-site/` | שער-סיסמה + לוח-בקרה + API-סוכנים (:3046) |
| `state/` | ריצה-בלבד — **git-ignored**, לעולם לא נדחף |
