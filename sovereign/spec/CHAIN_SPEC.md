# SAOS-NET — מפרט השרשרת-הריבונית (v0 "shadow anchored")

> זהו מפרט הרשת-שלנו. הרשת יושבת **על העיגונים** של Steem+Hive אבל המצב,
> הכללים, הגז וההסכמה — שלנו. מפרט זה קבוע-חוזה ל-v0: שינוי = fork
> מתועד ב-worklog.

## 1. עקרון-על

**המצב הוא מתמטיקה, העיגון הוא ראיה.**
כל מצב של SAOS-NET הוא עץ-JSON קנוני שה-root שלו הוא sha256.
הרשת המארחת (Steem/Hive) לא מחזיקה את המצב — היא מחזיקה **ראיות**:
צ'קפוינטים (state-root) + הצהרות-ולידטורים (attests), כולם custom_json
חינם-RC. מי שמחזיק ג'נזיס + אוגר-הבלוקים משחזר את העולם ומאמת כל
צ'קפוינט מתמטית — בלי לסמוך על שרת כלשהו.

## 2. יחידות ואריתמטיקה (קבוע)

| יחידה | ערך | שימוש |
|---|---|---|
| µ (micro) | 1 SAOS = 1,000 µ · 1 STEEM = 1,000 µ | כל היתרות |
| µp (micro-price) | 1.0 = 1,000,000 | מחירי-הזמנות |
| µlp | 1.0 LP = 1,000,000 µlp | מניות-בריכה |

**אסור float במצב.** כל החישובים שלמים; חלוקה = floor; שימור
נבדק: `in == (net + feeToLp) + feeToTr` בכל swap.

## 3. מבנה-מצב (state shape)

```json
{
  "meta": { "height": 0, "supply": 68000, "lastBlockHash": "…64hex",
             "lastTime": "ISO", "yieldDay": "YYYY-MM-DD", "pays": 0,
             "trades": 0, "swaps": 0, "yieldTotal": 0, "lastHeartbeat": "…" },
  "accounts": { "<name>": { "saos": µ, "steem": µ, "lockedSaos": µ,
                 "lockedSteem": µ, "lp": µlp, "wrapped": {"SYM": µ},
                 "credits": µ } },
  "orders": [ { "id": 1, "side": "sell|buy", "owner": "name",
                "amount": µ, "price": µp, "live": true, "at": "ISO" } ],
  "nextOrder": 2,
  "pool": { "saos": µ, "steem": µ, "lpSupply": µlp, "feeBps": 30 },
  "fees": { "total": µ, "toLp": µ, "toTreasury": µ },
  "wrapped": { "SYM": { "locked": µ, "supply": µ, "redeemed": µ,
                 "refs": {"<ref>": true} } },
  "attests": { "<stateRoot64hex>": ["validator", …] },
  "weave": { "nextSeq": 1, "nextSeal": 1, "total": 0,
             "stamps": { "<h>": { "h", "seq", "kind", "by", "at", "salt" } },
             "seals": [ { "seq", "root", "count", "from", "to", "at" } ],
             "witnesses": { "<topic>:<claimHash>": ["validator", …] },
             "lastSeal": { "seq", "root", "count", "at" } },
  "checkpoints": [ { ראה §6 } ]
}
```

**WEAVE (W1.3.1)**: מצב-האריגה ממומש **עצלנית** — עד-החותמת/איטום/עדות-הראשונה
המפתח `weave` לא קיים-כלל במצב (אותו-חוק של `producers`). לפני-כן stateRoot
זהה-byte-למקור — שינוי אדיטיבי ללא-fork היסטורי. קבועי-גבול: ≤1024 חותמות-חיות,
≤32 איטומים-בטבעת, ≤64 נושאי-עדות (ההיסטוריה המלאה = ה-block log עצמו).

גבולות-מצב קבועים (למניעת נפיחה): ≤32 צ'קפוינטים במצב, ≤256 refs
לכל עגון, ≤8 הזמנות-חיות/בעלים. `treasury` הוא חשבון-מערכת
(מנפיק-עגונים, מחלק-תשואה, קולט-חלק-עמלות).

## 4. טבלת-פעולות (ops) + גז

| op | גז | חוקי-עסקים עיקריים |
|---|---|---|
| `transfer` | 100 | יתרה-מספקת; אין self; `to` נוצר-אוטומטית |
| `pay` | 120 | כ-transfer, נספר ב-`meta.pays` — מסילת-הסדרה |
| `order` | 150 | sell: נועל SAOS · buy: נועל STEEM (ceil); cap 8 חיות |
| `cancel` | 60 | רק-בעלים; משחרר נעולים |
| `fill` | 200 | cross הזמנה-חיה; אסור self-trade; מזיז SAOS+STEEM; `lastPrice` |
| `pool_add` | 180 | מניות יחסיות (ראשון: 1e3 µlp ל-µ); רצפת 1 µlp |
| `pool_swap` | 220 | x·y=k עם עמלת `feeBps` (floor); LP½ + treasury½ |
| `wrap_mint` | 250 | רק-treasury; **ref חד-פעמי**; מרוצף-מטה: `(supply+a)/locked ≤ 1.0001` |
| `wrap_burn` | 250 | **דורש החזקה** — פדיון-פנטום נדחה; סופר `redeemed` |
| `yield` | 150 | רק-treasury; idempotent-יומי לפי `day` |
| `attest` | 50 | ולידטור מצהיר על stateRoot; dedupe לפי (validator, hash) |
| `heartbeat` | 10 | מצב-אימפריה חי → `meta.lastHeartbeat` (עד 160 תווים) |
| `stamp` | 20 | WEAVE: `{h 64hex, kind 2-16ch, by, salt?}` — h יחיד-עולמית (dedupe=exists); ≤1024 חיים (מעבר=seal-required) |
| `seal` | 60 | WEAVE: רק-המנפיק; `{root, count}` — **הקרנל עצמו מחשב את שורש-המרקל הקנוני מהחיים ודוחה כל אי-התאמה** (root-mismatch/count/empty); אחרי-הצלחה: החיים מתרוקנים, seal נכנס לטבעת-32 |
| `witness` | 40 | WEAVE: עדות-צי `{topic, claimHash, validator}` — dedupe לשלישייה; קוורום-ספירה = שכבת-השאילתה |

גז v0 = מדידה-בלבד (מסוכם ב-`gasUsed` לכל בלוק). תמחור-גז אמיתי — v1.

### 4.1 WEAVE — עלה-המרקל הקנוני (W1.3.1)

```
leaf = sha256(canon({ h, seq, kind, by, at, salt }))   ← אותו-עצם שב-stamps
עץ:   צומת = sha256(L‖R) · מפלג-אי-זוגי = כפילות-האחרון · על-יחיד = הוא-השורש
```

- העלים נגזרים **מה-block log הציבורי** (ה-stamp-ops עצמם) — כל-אדם משחזר
  את העץ ואת נתיבי-ההוכחה בלי לסמוך על אף-שרת (אותו-חוק של kernel-replay).
- ה-seal הוא החוזה: הקרנל מסרב לכל root שאינו שווה-בדיוק לשורש-הקנוני
  של הרישומים-החיים. אין חותם-מזויף. אין חותם-חלקי. אין חותם-כפול.
- הוכחת-חותמת בודדת = נתיב ~1KB + txid-העיגון של הצ'קפוינט שנשא את-השורש.

### 4.2 WEAVE — הבאצ'ר-השעתי (W2, מאומת-חי)

**זרימה (הפרדת-סמכויות):** הבאצ'ר מחשב, הצומת כותב, הקרנל מחליט.

```
א. agent/weave_batch.cjs (לולאת-weaveBatch בדמון, שעתית) — replay עצמאי
   מלא (ג'נזיס+בלוקים, כמו-הצומת) → אם יש רישומים-חיים ו(חלף-שעה מהאיטום
   האחרון או live ≥ 768/1024) → שורש-קנוני → weave-request.json
   {protocol:"saos-weave/v1", action:"seal-request", root, count, from, to, computedAt}
ב. הצומת (הכותב-היחיד, תחת-beat.lock) קורא את-הבקשה בפעימה ומגיש op `seal`
   עם root מהבקשה — הקרנל מחשב-בעצמו מהחיים ודוחה כל-אי-התאמה. שורש-ישן
   (stamps חדשים-ביניים) = root-mismatch → הבקשה נבלעת, הבאצ'ר יחשב-מחדש.
ג. אחרי-האיטום: הצ'קפוינט-הבא (≤12-בלוקים) נושא את-השורש בתוך ה-stateRoot.
ד. עיגון (הבאצ'ר, רק-מה-seals שהקרנל אישר — state.json → weave.seals):
   Steem custom_json (active, חינם) + Hive custom_json (active, חינם) +
   Blurt custom_json (רק-קצוות-חיים, cool-down מדוד) — id="saos.weave.v1",
   payload {protocol:"saos-weave/v1", action:"seal", net, seq, root, count, from, to, height, time}
   · TRON = טרנזיטיבי: הצ'קפוינט-הראשון מעל-גובה-האיטום מעוגן-יומית ע"י
     מסילת-הגשר-הקיימת (השורש בתוך ה-stateRoot) — אפס-הוצאה-חדשה.
ה. הוכחה-עצמאית: העלים נבנים-מחדש מה-block-log בלבד → שורש==seal.root →
   prove+verify לעלה-הראשון → תעודה ב-agent/weave_last.json (ציבורי, בלי-סודות).
```

- **ספי-איטום:** `WEAVE_SEAL_GAP_MIN` (ברירת-מחדל 60 דק') · `WEAVE_SEAL_PRESSURE` (ברירת-מחדל 768 מתוך קיבולת-חיים 1024 — איטום-מנע לפני `seal-required`).
- **dedupe-עיגון:** `agent/weave_state.json` — עיגון-אחד-לכל-sealSeq (טבעת-64); כישלון-שידור נרשם כנה ויינסה בפעימה-הבאה.
- **הזרקת-מפעיל:** `node saosnet.cjs --inject file.json` — בלוק-אחד של stamp/witness תחת-הנעילה; נתיב-ההזרקה-הכנה עד-ה-API (W3). הקרנל מאמת-הכל.
- **stopgap-W2:** `MAX_BLOCKS_KEPT` 512→4096 — truncation מתחת-לגובה-החי הייתה-שוברת את-ה-doctrine של replay-מג'נזיס (הפתרון-האמיתי: base-snapshot ב-replay — נרשם ב-worklog).
- **מאומת-חי (סנדבוקס):** 3-חותמות-אמת (THE_WEAVE.md · קומיט-W1 · merkle.cjs) → seal#1 root `75b011b8…` בלוק-503 → צ'קפוינט-504 נושא-אותו → הוכחה-עצמאית ירוקה · שורש-מזויף נדחה `root-mismatch` · שער-השעה נאכף.

## 5. בלוקים

```json
{ "height": 1, "time": "ISO", "prevHash": "…|null",
  "txs": [ … ], "results": [ {"ok":true,"gas":100,…} ],
  "gasUsed": 100, "hash": "sha256(canon(block))" }
```

ה-hash מחושב **בלי** שדה-`hash` עצמו. בלוק לא-חוקי בטרנזאקציה לא נופל —
ה-tx מסומן `ok:false` עם `err` והמצב לא נפגע (השרשרת זוכרת ניסיונות).

## 6. הסכמה — Anchored Quorum (v0)

כל `CHECKPOINT_EVERY=12` בלוקים נבנה צ'קפוינט:

```json
{ "height": 12, "blockHash": "…", "stateRoot": "…", "supply": 68000,
  "time": "ISO", "validator": "headcorner",
  "anchors": { "steem": "txid|pending", "hive": "txid|pending|skipped-rc" },
  "quorum": { "required": 3, "attests": ["soldier1", …] } }
```

- **ראש-הרשת** (headcorner) בונה בלוקים וצ'קפוינטים — הוא ה-anchor-writer
  v0 (פשרה-מתועדת: ריבונות-מצב מלאה, הסכמה-סופית v1 = round-robin ראשים).
- **ולידטורים = החיילים.** כל חייל חותם `attest` על ה-stateRoot **במפתח-שלו**
  (custom_json id='saos' protocol 'saos:net/v1' על Steem — חינם-RC; Hive כשיש
  דלק). quorum v0 = 3 חותמות.
- **עיגון**: צ'קפוינט נשלח על Steem (posting, חינם-RC) ועל Hive (fleet-router,
  RC-gated-כנה). `anchors` מתעדכן ב-txids לאחר אימות get_transaction
  על צומת-עצמאי.
- אימות מקומי: `verifyCheckpoint(cp, st)` — stateRoot חייב להתאים למצב
  המקומי ששוחזר מג'נזיס+בלוקים; quorumMet = attests ≥ required.

## 7. הג'נזיס — נגזר, לא מומצא

`sovereign/genesis/genesis.json` נוצר ע"י `derive-genesis.cjs --live`
מה-replay-המאומת של הדקס/עגונים/מיקרו-דקס (מהשרשראות המארחות עצמן!).
כל-מספר נושא `sources` — מאיפה הגיע. לאחר ה-derivation, `genesisHash`
(sha256 קנוני) נעוגן on-chain — מרגע-זה הרשת-שלנו נולדת ממצב-שכולו
ראיות-ציבוריות.

## 9-b. MIRROR + ECONOMY — שלבים 1+2 (מאומת-חי)

אירועי-האימפריה-האמיתיים זורמים-לתוך-השרשרת-הריבונית — והספר-הריבוני-עצמו מארח-סחר:

| אירוע-מארח | טרנזאקציה-ריבונית | הערה |
|---|---|---|
| מכירת-סוחר (transfer+memo saos:buy) | `transfer` (אוצר→קונה, מסירה) + `steemPay` (host→אוצר, הכנסה) | ref=host-txid |
| תשואה-ממומנת-עמלות | `steemPay` (אוצר→host, יציאה-מעבר-לגבול) | ref=host-txid |
| pool_add חייל | `pool_add` (owner=חייל) | דורש-יתרה-ריבונית — נכשל-כנה-אם-חסר (SOVFLO פותח-זאת) |
| pool_swap חייל | `pool_swap` (sell_saos) | הבריכה-הריבונית-מתכנסת-לבריכת-המארח |
| **order-buy/order-sell חייל (70)** | `order` (owner=חייל, side+price מהמחרוזת-החתומה) | ref=ord:host-txid · מיפוי-txid→orderId-ריבוני-נשמר |
| **fill-מארח (70)** | `fill` (taker=חייל, נגד-הזמנה-חיה-של-ה-maker, טולרנס-מחיר 1%) | ref=fil:host-txid · אין-התאמה → דילוג-כן-מסופר (לא-המצאה) |
| **(70) יתרות-מארח-מדודות** | `transfer` (אוצר→חייל, SAOS מ-dex-ledger) + `steemPay` (host→חייל, STEEM נזיל-חי) | refs flo:/fls:<acct>:<day> — הצפה-יומית-idempotent |
| **(70) שאלת-עומק-אוצר** | `order` sell @lastPrice×1.003 (0.25 SAOS), ממוחזרת-בסטיה->2% | ref=ask:<day>:<seq> · המחיר-נגזר-מהמארח, לא-מומצא |
| **(70) התאמה-ריבונית** | `cancel` (שחרור-bid) → `fill` (במחיר-ה-ask — שיפור-מחיר-ל-taker) | refs cxl:/mat: · price-time-priority, cap 4-זוגות/פעימה |
| **(70) תשואה-ריבונית** | `yield` (מהמנפיק-החי, ממומנת-fees.toTreasury-של-השרשרת-עצמה) | day-dedupe-קרנל · cap 0.02 SAOS/יום · לפי-מניות-LP |

- **'host' = חשבון-גבול**: רשאי-יתרה-שלילית; הוא-הסמן-המצטבר-של-הזרימה-נטו
  של-STEEM מעבר-לגבול-מארח/ריבוני (כמו-חשבון-פיקדון-בבורסה). אחרי-SOVFLO-70:
  ‑0.061 STEEM — הזרימה-אלינו-נמדדת-על-השרשרת.
- **פנקס-כפול**: cursors ב-state.json + refs-על-השרשרת — אירוע-לא-מומר-פעמיים.
- ניסיון-מראה-כושל (יתרה-חסרה) נרשם בבלוק כ-ok:false — השרשרת-זוכרת-גם-כישלונות.
  (הזמנות-שנכשלו-בגלל-הצפה-שטרם-הגיעה: ה-txid-נצרך — הזרימה-ממשיכה-מהפעולות-הבאות-על-המארח).
- **kernel v1.2**: `yield` משלם-מהמנפיק-החי (`st.meta.issuer`, כמו-feeToTr) —
  בווקטורים-אין-issuer → 'treasury' → **וקטורי-הקביעות לא-נשברו** (366ad477).
- **חומת-כנות-70**: fill-מארח מומר-רק-כשקיימת-הזמנה-ריבונית-חיה-של-ה-maker-בטולרנס-מחיר;
  אחרת דילוג-מסופר — לא-ממציאים-התאמות.

## 10. חומות-ידועות (כנות)

- v0 ראש-יחיד: ה-מצב דטרמיניסטי-ומאומת אבל **סדר-הבלוקים** נקבע ע"י
  הראש. round-robin מתוכנן ב-שלב-3.
- גז v0 מדיד-ולא-מתומחר.
- get_transaction מפגר דקות (תגלית-66) — אימות-מחוזק 5 ניסיונות × 3 צמתים × 8 שנ'.
- אין עדיין עדי-צ'קפוינט עצמאיים מספיק — quorum=3 מהצי שלנו. הרחבה = עוד
  ולידטורים חיצוניים עם מפתחות-פרסום-עצמאיים.
- **תגלית-69 (race)**: שתי-פעימות-מקבילות (דמון+ידני) ייצרו-שרשראות-אחיות —
  הקבצים-האחרונים-היו-עקביים-פנימית (אומת: 27/27-בלוקים) אבל-אח-אחד-היה-עלול-

## 11. EXPLORER + ROTATION — Task 71 (מאומת-חי)

### 11-a. EXPLORER — תיעוד-הרשת-על-הרשת

האקספלורר הוא הפנים-הציבוריות של SAOS-NET — והרשת מתעדת את עצמה:

- **אימות-שלמות חי (API /api/ops/sovexplorer)**: בכל קריאה האקספלורר מריץ
  replay מלא **דרך הקרנל עצמו** — genesis → כל-בלוק נבנה-מחדש עם
  `K.buildBlock` (hash + results + gas מושווים), שורשי-המצב-מתועדים-לפי-גובה
  (כל-צ'קפוינט מאומת מתמטית מההיסטוריה-הקנונית), וה-root הסופי מושווה
  למצב-הצומת. זהו אימות-רציף, לא דגימה. **שיטה-חשובה**: ה-hash-המקורי חושב
  על-אובייקט-חי שבו-מפתחות-undefined (`filled/out/shares/orderId` ב-results)
  נכללים ב-canon — ה-replay דרך-המנוע משחזר-את-הצורה-במדויק (גילוי-71).
- **publications (תיעוד-ציבורי)**: כל-פעימה-שנייה (קצב 30 דק') הצומת מפרסם
  `custom_json` ציבורי על Steem (protocol `saos:net/v1`, `action: 'explorer'`)
  עם תמצית-הרשת: height · stateRoot · genesisHash · supply · txs · accounts ·
  asks/bids · trades · lastPrice · feesµ · yield · boundary · cp-אחרון
  (height+stateRoot+steem-txid) · time · **digest** =
  `sha256(canonicalJSON(core))` על גוף-התמצית בלי-ה-digest.
  משמעות: כל-אחד-על-המארח יכול לעקוב-ולאמת את SAOS-NET בלי-גישה-לשרת.
  ה-publications נרשמים ב-state.json (`explorer.publishes`, cap 24) ומאומתים
  `get_transaction` כמו-כל-עיגון (kind `explorer-pub`).
- **ראוטינג-עיגון**: ה-publication עובר דרך אותו-ראוטר (ראש→צי, שערי-RC) —
  התיעוד-מעולם-לא-נעצר; דילוג-נרשם-בכנות.

### 11-b. ROTATION — רוטציית-ולידטורים (stage-3 groundwork)

- סדר-ההצהרות (attests) נגזר-מהשרשרת עצמה: `round = floor(height/12)`,
  `offset = round mod |army|` — הצבא מסובב-מנקודת-הסבב, ומי-שנמצא-בתקציב
  (3/חייל/יום) או-מתחת-שער-הדלק (RC<40%) מדלג-בכנות.
- הרוטציה מוכחת-על-השרשרת: payload ההצהרה נושא `round`, וה-txids הציבוריים
  מראים-מגוון-ולידטורים-לאורך-הסבבים.
- זהו-הצעד-הראשון-לשלב-3 (ראשים-מתחלפים): ההסכמה עדיין-ראש-יחיד, אבל
  **סדר-המשתתפים-נקבע-מתמטית-מהגובה** — אותו-חוק-שיקבע-את-מפיקי-הבלוקים.

## 12. STAGE-3 ROTATION — ראשים-מתחלפים (Task 72, מאומת-חי)

### 12-a. חוק-הרוטציה (הראש-נגזר, לא נבחר)

- **החוק**: `producer(round) = roster[round mod |roster|]`, כאשר
  `round = floor(height/12)` ו-`roster` = שמות-החיילים-ממוינים (קנוני).
  החוק כולו נגזר-מהגובה-ומהרוסטר — אף-אחד לא "בוחר" ראש.
- **ROSTER — הרוסטר פומבי**: `custom_json` על המארח
  (`protocol saos:net/v1`, `action: 'roster'`) נושא את-הרוסטר הממוין
  ואת-`digest = sha256(canonicalJSON(roster))`. הפרסום יומי-idempotent
  (רוסטר-משונה-שינוי = digest-חדש = פרסום-חדש). ה-digest נושא בכל-
  publication-אקספלורר — צד-שלישי יכול לאמת את-החוק מהמארח בלבד:
  לקחת רוסטר מפורסם, לחשב `roster[floor(h/12) mod N]`, ולהשוות
  ל-`produce`-שעל-השרשרת.

### 12-b. הפעולה `produce` (קרנל v1.3, op 14)

- `{ type: 'produce', producer, round, ref }` — גז 30.
- **אכיפה-קונסנסואלית**: הקרנל אוכף ראש-אחד-לסבב — `st.producers[round]`
  קיים → `err: 'dup-round'`. הקרנל אינו יודע את-הרוסטר (נתון-סביבה);
  הוא אוכף מבנה (producer תקין, round שלם ≥ 0, ref לא-ריק) ואת-האכיפה.
  **בדיקת-החוק** (producer == נגזרת-הרוסטר) נעשית מחוץ-לקרנל — ע"י
  האקספלורר, ה-publications, וכל-צד-שלישי.
- **מצב**: `st.producers[round] = { producer, ref }` (prune 32-סבבים-אחרונים,
  כלל-נומרי-דטרמיניסטי) + `meta.lastProducer/lastProduceRound`.
  יצירה-עצלנית של `st.producers` — מצב-טרם-הפקה-ראשונה byte-זהה
  (וקטורי-הקביעות 366ad477 לא נשברו; וקטור-רוטציה חדש b8ee2ee8).
- **ראיה-על-המארח**: המפיק-הממונה חותם `custom_json`
  (`action: 'produce'`, round+height+producer+genesisHash) במפתח-שלו —
  כמו-attest: סמכות-על-המארח, ביצוע-דטרמיניסטי-בקרנל. ה-op הריבוני
  נכנס בבלוק-ה-heartbeat של-הפעימה-הראשונה-בסבב, ref=`prc:<round>:<txid>`.

### 12-c. פערים-כנים

- מנדט-שלא-הוכח (אין-מפתח / RC<40% / שידור-נכשל) = **הסבב נשאר בלי
  produce-op** — החוק-מעולם-לא-מופר, הפער מתועד (nodeSt.rot.misses +
  heartbeat-note `head-miss r<round> @<producer>(<why>)`). סבב-חדש
  מביא-ראש-חדש לפי-החוק; אין-החלפה-ידנית-של-מנדט.
- **תגלית-72 (checkpoint-boundary)**: בדיקת-צ'קפוינט-יחידה-בסוף-הפעימה
  דילגה-על @60 — בלוקי-כלכלה חצו-את-הגבול (60→61) לפני-הבדיקה.
  תיקון: `maybeCheckpoint` אחרי-כל-שלב-בנייה (idempotent לפי height%12).
  @60 נשאר פער-היסטורי-כן (השרשרת-מסומנת-מ-@48-ישר-ל-@72). הלקח:
  תנאי-גבול חייב-בדיקה-בכל-נקודת-חיתוך, לא בסוף-התהליך.

### 12-d. מה-נשאר לשלב-3 מלא

- ההפקה-עצמה (סדר-הבלוקים) עדיין-מופעלת-ע"י-תהליך-הצומת-היחיד — החוק,
  האכיפה, והראיות כבר-מפוזרים. שלב-3-מלא: תהליך-צומת-עצמאי-לכל-מפיק
  שמפיק-בלוקים-רק-כשהחוק ממנה-אותו (המנוע-הדטרמיניסטי-מאפשר-זאת-כבר-עכשיו:
  כל-מכונה-עם-הג'נזיס+הבלוקים משחזרת-את-המצב ומאריכה-בתור-הראש-הנגזר).

### 13-b. חבילת-אימות (`?export=verify`)

- **האקספלורר לא רק מציג את הרשת — הוא מחזיק את הראיות**: הורדת JSON אחת שמכילה ג'נזיס + שרשרת-מלאה + כל-הצ'קפוינטים + stateRoot + הרוסטר-החוקי + digest.
- `digest = sha256(canon({genesisHash, blocks, checkpoints, stateRoot}))` — ה-canon של **הקרנל-עצמו** (אותו-canonicalJSON של stateRoot/blockHash), כולל הוראות-replay שלב-אחר-שלב לצד-שלישי.
- מי-שרץ את הקרנל הדטרמיניסטי על החבילה מקבל את ה-hashים והשורשים-בדיוק — **אימות-עצמאי מלא בלי לגעת בשרת**. זו הסגירה-המלאה של "תיעוד-הרשת-על-הרשת": פרסומים-חיים על המארח (§11-a) + חבילת-ראיות-מלאה להורדה.

## 15. ROAST 117p8-R8 — אמת-מציאות של השרשרת-עצמה (מדוד-חי, מתוקן)

ביקורת-עצמית-חריפה (agent/chain_audit2.cjs · chain_forensics.cjs — replay מלא
דרך-הקרנל, hash-פר-בלוק, פורנזיקה). מה נמצא-ומה תוקן:

### 15-a. מזלג fill-buy (CRITICAL — תוקן-בחוק-מספר)

- **הפער**: ענף-`fill` על הזמנת-`buy` רד **הפוך** מכוונתו המוצהרת: ה-taker
  *קיבל* SAOS+STEEM והבעלים *שילם* את-שניהם — 9,358 מילויים-חיים
  (Σ≈532K µSAOS זרמו מבעלים→taker), 1,944 הזמנות שחררו-יותר-מהנעול
  (+3,893µ), ויתרות-lockedSteem שליליות ב-11+ חשבונות (עד ‑462µ).
- **התיקון**: `FILL_BUY_FIX_HEIGHT = 130000` — קבוע-חוזה-בקרנל. מעליו:
  ה-taker (מוכר-ה-SAOS) חייב-להחזיק SAOS ומוותר-עליו; הבעלים מקבל; שחרור-הנעול
  מוגבל-במנעול-הקיים (אף-שלילי). מתחתיו — הסמנטיקה-ההיסטורית byte-זהה
  (replay-של-העבר לא נשבר). וקטור-קבוע חדש `selfTestFillBuy` מוכיח שני-הענפים.

### 15-a2. שריפת-SAOS בבריכת-הגשר (CRITICAL — תוקן-באותו-מזלג)

- **הפער**: `pool_swapw` לא זיכה את ה-taker בפלט-החלפה **בשני-הכיוונים**:
  sell_wtrx שרף את ה-SAOS-שיצא-מהבריכה (`p.saos -= out` ואף-אחד-לא-קיבל) —
  buy_wtrx שרף את ה-WTRX באותו-אופן. **נמדד-חי ב-replay-שימור-מלא (ΔT פר-בלוק):
  ~111 SAOS נשרפו** מאז-היווסד (T0=198,167µ → 87,184µ); הבלוקים-הראשונים-
  הדולפים: h784/h802/h838/h849/h885/h896. שים-לב: הקרנל שמר-על-כל-שאר-ה-ops —
  זה-היה הפער-היחיד; pool_swap/pool_x (98) נבדקו-ותקינים.
- **התיקון**: אותו-שער `FILL_BUY_FIX_HEIGHT=130000` (נבדק: אפס-החלפות-WTRX
  ב-130000..130239 — המזלג-נקי). מעליו ה-taker מקבל את ה-out (שימור-מלא,
  וקטור `swapw-conserved`); מתחתיו ההיסטוריה byte-זהה (וקטור `swapw-legacy-burn`
