## 0. חוק-התמותה ומבחן-ההעברה (MTT)

הריבונות = git + Actions + canon. כל דבר אחר הוא תהליך-חד-פעמי.

**מבחן-ההעברה (Mortality-Transfer Test)** — נשאל אחרי כל עבודה:
"אם הסוכן מת מיד אחרי ה-commit, האם 100% מהערך נשאר?"

תוצר עובר MTT רק אם הוא אחד מארבעה:
- **(a) חוק** — רשומה ב-DECISIONS/canon עם נימוק וקבלה
- **(b) מנוע** — workflow ניתן-להרצה ב-git (רץ בלי סוכן חי)
- **(c) מדידה** — ארטיפקט מדוד ב-state/ עם קבלה ומקור
- **(d) משטח** — מוצר חי שמשתמש אמת רואה

ערך שנשאר בצ'אט או בזיכרון-סוכן = בזבוט, גם אם הטסט שלו ירוק.
כל receipt נסגר מעתה עם הצהרת-MTT אחת: "מה נשאר אחרי המוות".

### מבדק C · אמת-ערך (VALUE-TRUTH AUDIT)
- **שאלה**: לכל workflow ירוק בכל ריפו — מי צורך את התוצר שלו? אם התשובה "הוא עצמו" = תיאטרון-ירוק.

- **מדד**: value-ratio = ארטיפקטים-נצרכים-ע"י-אמת ÷ סך-ארטיפקטים. יעד ≥ 0.7.
- **תוצר**: `docs/R332-VALUE-TRUTH-AUDIT.md` + תור: לחבר או להרוג כל תיאטרון-ירוק.
- **סיום**: אין workflow בלי verdict (TRUE-VALUE / INFRA-NEEDED / GREEN-THEATER).

  + החלטות פזורות ב-canon/receipts. חוק מפורק = חוק שנשכח. פעולה-ראשונה: מפת-רישומים אחת.
- **שיטה**: לכל רשומת-חלטה ולכל טענת-ריבונות ב-canon: (1) נכונה עדיין? (2) נאכפת מכנית

## 4. פרוטוקול-התנועה בין-סוכנים (נגד-דריסות)

1. לפני כעבודה: **לקרוא את worklog מהסוף** — לזהות נתיבים תפוסים ומה נסגר.
2. לתבוע נתיב: Task-ID ייחודי + **FILE-BOUNDARY מפורש** (על מה אני כותב / על מה אסור לי).
3. additive-only; אסור לגעת בקבצים של נתיב-אחר; מחלוקת = issue, לעולם לא rewrite.
4. זהות-חוקית בלבד (DECISIONS #10) · leak-scan לפני דחיפה · push עם rebase-retry מדורג · אין force.
5. כל נתיב נסגר עם הצהרת-MTT ב-receipt.
6. סוכן שמסיים נתיב **משאיר ידית ליורש**: מה נשאר פתוח, מה נמדד, מה חסר לסגירה.
