# TFA — תוכנית המימוש: מהקרנל לחידוש עולמי

מסמך אסטרטגי-הנדסי. נכתב אחרי אימות עצמאי של v20 (160/0/0 אמיתי; הסוכן עבד לפי התור: identity+delegation+signing+pg-ledger). מותאם למצב: מייסד יחיד + צוות סוכני-AI.

---

## 1. איפה אנחנו באמת (מאומת, לא משוער)

ה-kernel כמעט שלם — לראשונה יש לנו את כל אבני-הבניין של "פעולה מחויבת":

| פרימיטיב | מצב | הוכחה |
|---|---|---|
| Guarded Action (policy→execute→audit, fail-closed) | ✅ | 160 טסטים |
| Policy-as-Data (JSON governance) | ✅ | 7/7 + HTTP חי |
| Ledger μ¢ double-entry + solvency | ✅ + pg-ledger | טסטים חיים |
| Audit hash-chain + **חתימה קריפטוגרפית** | ✅ | 14/14 |
| Agent Identity + **Delegation chain** (אדם→סוכן→תת-סוכן) | ✅ | 15+14 |
| Tenant isolation | ✅ | HTTP חי |
| חסר: חיבור delegation ל-orchestrator כברירת-מחדל; Replay | ⬜ | תור הסוכנים |

**מסקנה:** סיימנו לבנות את היכולת. השלב הבא הוא להפוך אותה למשהו שהעולם לא ראה.

## 2. החידוש העולמי: ה-Action Passport (דרכון-פעולה)

**הרעיון בשורה אחת:** כל פעולה במערכת מנפיקה מסמך קריפטוגרפי נייד שמוכיח — לכל גורם חיצוני, בלי לסמוך עלינו — מי ביקש (שרשרת-ההאצלה עד האדם), איזו מדיניות אישרה, מה בוצע, ומה קרה לכסף.

למה זה חידוש שאין בעולם (נכון ל-2026):
- יש audit logs (כולם). יש חתימות (web3). יש agent frameworks (כולם). **אין** את החיבור: *הוכחת-אחריותיות ניידת לפעולת-AI* — artifact אחד, self-contained, שמאמת offline: delegation chain + policy decision + execution + ledger effect, חתום.
- זה עונה בדיוק על השאלה שהעולם מתחיל לשאול ואין לה תשובה: **"איך אני יודע שהסוכן הזה היה מורשה לעשות את זה?"** רגולציה (EU AI Act), ביטוח לסוכנים, B2B בין-סוכני — כולם צריכים את זה ואין סטנדרט.
- ה-moat: כל מי שמנפיק דרכונים נכנס לרשת-אמון שאנחנו הסטנדרט שלה. הדרכון הוא ויראלי מטבעו — הוא נשלח *החוצה* לגורמים שלא מכירים אותנו, וכל אימות שלו הוא חשיפה.

**טכנית זה קטן** (וזה היופי): יש לנו כבר את כל הרכיבים — signature, hash-chain, delegation chain, audit record, ledger transaction. הדרכון = פונקציית-אריזה שמלקטת אותם ל-JSON חתום + verifier עצמאי של ~100 שורות שכל אחד יכול להריץ. שבוע-עבודה של סוכנים, ערך של קטגוריה חדשה.

```
ActionPassport {
  version, passportId,
  action: { id, type, timestamp, tenantId },
  accountability: { rootHuman, delegationChain[], signatures[] },
  governance: { policiesEvaluated[], decision, reason },
  effect: { ledgerTx?, balancesDelta?, solvencyAfter? },
  chain: { auditId, prevHash, hash, signature },
  verify: "self-contained — independent verifier, no trust in issuer required"
}
```

## 3. כלכלת-העתיד "שתעבוד בוודאות" — עקרון התכנון

אתה לבד. לכן הארכיטקטורה חייבת להיות **certainty-first, לא scale-first**:

1. **ודאות לפני נפח.** כלכלה אמיתית לא נופלת מ"אין משתמשים" — היא נופלת מ"כסף נעלם פעם אחת". לכן: ledger persistent (יש), solvency אוטומטי אחרי כל פעולה (להוסיף כ-invariant, לא כ-endpoint), replay מאירועים (בתור), ו-property-based tests על ה-ledger (הסוכנים יכולים).
2. **המערכת היא העובד שאין לך.** כל דבר שדורש "מישהו ישים לב" — הופך ל-invariant אוטומטי שנכשל רועש. ה-quality gate שלנו (מנוע-האמת) הוא המנהל-איכות; ה-solvency check הוא רואה-החשבון; ה-passport הוא המבקר.
3. **קודם כלכלה סגורה, אז פתוחה.** קרדיטים פנימיים (μ¢) בלי פיאט = אפס סיכון רגולטורי, מלוא הלמידה. פיאט אמיתי רק דרך adapter מרושה, בשלב שיש הכנסות שמצדיקות עו"ד.
4. **אדם-אחד-בשליטה:** כל פעולה אוטונומית עוברת delegation עד אדם-שורש (אתה). תקרות ב-policy-as-data. זה לא רק בטיחות — זו *הדמו* של המוצר: מערכת שמוכיחה שאדם אחד יכול לשלוט בצי סוכנים באחריות מלאה.

## 4. תוכנית הביצוע (לפי סדר, לסוכנים + לי)

**שלב A — לסגור את ה-kernel (שבוע סוכנים):**
1. חיבור delegation ל-orchestrator כברירת-מחדל (כבר בתור של MANIFEST).
2. Solvency כ-invariant אוטומטי אחרי כל פעולת-ledger (לא רק endpoint).
3. Replay מ-outbox (כבר בתור).

**שלב B — החידוש (שבוע-שבועיים):**
4. `lib/passport/` — issuePassport(auditId) שמלקט chain+delegation+policy+ledger לחתום אחד.
5. `verify-passport.mjs` — verifier עצמאי אפס-תלות (אפשר לפרסם כקובץ בודד). **זה המוצר השיווקי הראשון:** כל אחד בעולם יכול לאמת דרכון בלי לסמוך עלינו.
6. Endpoint: GET /api/passport/:auditId + הנפקה אוטומטית לפעולות כספיות.

**שלב C — ההדגמה החיה (הדבר שמביא עולם):**
7. ה-Potential Engine רץ כסוכן אוטונומי *בתוך* המערכת: מקבל delegation ממך, פועל תחת policy-as-data, כל המלצה שלו נושאת passport. **הדמו: "סוכן AI שמנהל כלכלה אמיתית באחריות מלאה מוכחת"** — אף אחד לא יכול להראות את זה היום.
8. דשבורד אחד פשוט: השרשרת, היתרות, הדרכונים — שקיפות חיה.

**שלב D — פתיחה (רק אחרי A-C):** SDK לצד-שלישי להנפקת/אימות דרכונים; ואז marketplace כשיש נזילות.

## 5. מה לא לעשות (תזכורת מהניתוח, מותאם ללבד)
- לא להרים multi-region/k8s — Postgres אחד + backup זה הוודאות שלך עכשיו.
- לא לבנות UI מפואר לפני שלב C — הדשבורד הוא הדגמה, לא מוצר.
- לא פיאט, לא KYC, לא token ציבורי — עד שיש משיכה שמצדיקה רישוי.
- לא להאמין לאף ירוק בלי להריץ את מנוע-האמת (הוכח שוב היום שזה עובד).

## 6. השורה התחתונה
יש לנו kernel חתום, מזוהה, ומבוקר — מה שחסר לעולם הוא **הוכחה ניידת**. ה-Action Passport הופך את מה שבנינו מ"backend טוב" ל"שכבת-האמון שסוכני העולם יצטרכו" — בעבודה טכנית קטנה, כי כל הקשה כבר בנוי. המייסד-היחיד הוא לא חולשה בתוכנית הזו: המערכת בנויה כך שהאחריותיות היא אוטומטית, והדמו עצמו הוא "אדם אחד, צי סוכנים, אפס אמון עיוור".
