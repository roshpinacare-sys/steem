# v32.3 External Qualification Execution Kit

## Purpose

This kit closes the internal readiness gap for the six external gates. It does **not** claim those gates have been executed. Production promotion remains blocked until observed, independently reviewed and signature-verified evidence is supplied for the exact source digest.

## Required evidence files

Place the following files in a directory outside the repository or in a disposable qualification lane:

1. `hsm-kms.json` — authorized custody, attestation, private-key non-exposure, unauthorized denial, rotation, revocation and outage behavior.
2. `monotonic-witness.json` — signed sequential receipts, rollback rejection and equivocation rejection.
3. `postgres-ha-pitr.json` — PostgreSQL 16+, distinct primary/standby, FORCE RLS, tenant probes, pool reset, failover during commit and PITR with measured RTO/RPO.
4. `human-pilot.json` — preregistered thresholds, consent, at least five participants, baseline/assisted outcomes and no synthetic rows.
5. `independent-review.json` — signed independent penetration, isolation, supply-chain and licensing PASS verdicts with no open high-severity blockers.
6. `multi-host-slo.json` — at least three hosts, one hour and 1000 requests, latency/error/revocation/recovery thresholds, no split brain and no stale authorization.

Every file contains a common `envelope` matching `schemas/external-evidence-envelope.schema.json`.

## Execution

```bash
npm run build:clean:v32
node scripts/evaluate-external-qualification-v32_3.mjs /absolute/path/to/evidence-directory
```

The evaluator writes `evidence/generated/V32_3_EXTERNAL_QUALIFICATION.json`.

## Fail-closed rules

- Missing input produces `NOT_EXECUTED`, never PASS.
- `SIMULATED` or `COMPUTED` evidence is rejected.
- Self-review is rejected.
- Unverified signatures are rejected.
- Source-digest mismatch is rejected.
- One failed gate blocks the aggregate gate.
- Even six passing gates only produce `eligible-for-authorized-decision`; governance authority must still decide.

## Human and legal boundaries

The pilot requires informed consent and anonymized participant identifiers. Licensing review is a qualified legal/professional input and is not generated by this repository. Independent security assessors must be organizationally separate from the platform owner.
