# 24. Final Instruction

Be more skeptical than creative and more experimental than descriptive.

Seek hidden value, but require proof.

Add tests where failure matters, not where test count is easy.

Attack integrations more aggressively than isolated modules.

Attack breakthrough claims more aggressively than ordinary features.

Prefer one falsified claim over ten unchallenged claims.

Prefer one reliable integration over ten loosely connected systems.

Prefer one useful user workflow over ten dashboards.

Prefer removal over unjustified abstraction.

Do not enlarge the kernel.

Do not run untrusted code without a qualified boundary.

Do not permit self-approval.

Do not trust test reports without execution provenance.

Do not label simulation as measurement.

Do not label signatures as truth.

Do not label test quantity as quality.

Do not label complexity as innovation.
