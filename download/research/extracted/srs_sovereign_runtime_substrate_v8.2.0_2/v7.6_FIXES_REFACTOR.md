### Fix 4: TypedDicts for payloads — ✅ Already done by F8

`srs/types.py` defines a TypedDict per task kind and a `TaskPayload`
union alias:

- `IdentifyPayload`, `IdentifyHardPayload`, `SearchPayload`,
  `OptimizePayload`, `VerifyPayload`, `ComputePayload`,
  `StorePayload`, `AmortizePayload`
- `TaskPayload = IdentifyPayload | IdentifyHardPayload | ... | AmortizePayload`

`Task.payload` remains `dict[str, Any]` for runtime flexibility (the
pipeline still reaches into it with bare subscripts); callers who want
static type-safety can opt in via the `TaskPayload` union alias. The
runtime guard is `_validate_task()` at execute()/plan_task() entry.

### Fix 5: TaskKind Enum — ✅ Already done by F8

`srs/types.py` defines:

```python
class TaskKind(str, Enum):
    IDENTIFY = "identify"
    IDENTIFY_HARD = "identify_hard"
    SEARCH = "search"
    OPTIMIZE = "optimize"
    VERIFY = "verify"
    COMPUTE = "compute"
    STORE = "store"
    AMORTIZE = "amortize"
```

Subclassing `str` means `TaskKind.IDENTIFY == "identify"` is `True` and
the enum serializes transparently to JSON. `Task.__post_init__`
normalizes the enum form back to its string value so downstream code
(persistence, logging, equality checks) sees a consistent `str`.
