## 1. Problem Statement

Two LOW-severity findings from the R17 security audit and one INFO-level
note from the R16 code-review roast remained open after v7.7:

### R17.13 (LOW) — Log injection via task_id

`task_id` is sanitized at the input boundary (R17.9 in
`Task.__post_init__`, R18 C4 via the `task_id` property setter), but
**defense in depth** requires that logging also sanitize user-controlled
values. A future code path that bypasses the input validator (e.g. a new
API endpoint that forgets to call `_sanitize_task_id`, or a property
mutation after construction) would re-open the log-injection vector:

```python
# Without log-side sanitization:
task_id = "evil\ngreen INFO execute: complete task_id=fake"
logger.info("execute: complete task_id=%s ...", task_id)
# → emits TWO log lines, the second of which looks like a legitimate
#   "execute: complete" record. A log-based alerting / SIEM rule
#   watching for "execute: complete" would fire on the injected line.
```

### R17.11 (LOW) — SRS_HOME unvalidated

`default_path()` read `SRS_HOME` verbatim and used it as the
snapshots-directory base:

```python
def default_path() -> Path:
    base = os.environ.get("SRS_HOME")
    if base:
        return Path(base) / "snapshots"
    return Path.home() / ".srs" / "snapshots"
```

A malicious or misconfigured `SRS_HOME=/dev/null` would cause every
`save()` to raise `NotADirectoryError` deep in `_atomic_write_json`
(bricking the CLI's `--persist` path). `SRS_HOME=/proc/self/fd/...`
could clobber an unrelated open file descriptor. `SRS_HOME=/etc/passwd`
(a regular file) would either fail or silently clobber the file.

### R16.10 (INFO) — Structured logging formatter

The CLI used `logging.basicConfig` with a plain `logging.Formatter`.
No second-layer defense against log injection: if a value slipped past
input validation, the newline would reach the log file verbatim.

## 2. Fixes Applied

### Fix 1 — `_safe_log_value` helper (R17.13)

Added to `srs/persistence.py`:

```python
def _safe_log_value(value: Any, max_len: int = 64) -> str:
    """Sanitize a value for safe inclusion in log messages."""
    s = str(value)
    # Remove control characters (except space) and non-ASCII bytes.
    s = ''.join(c for c in s if c == ' ' or (32 <= ord(c) < 127))
    if len(s) > max_len:
        s = s[:max_len] + "..."
    return s
```

Behavior:
- Strips every control char (`\n`, `\r`, `\t`, `\x00`, `\x1b` ESC, etc.)
- Strips non-ASCII bytes (defensive against Unicode normalization tricks)
- Truncates to 64 chars (configurable) to prevent log flooding
- Preserves printable ASCII (32–126) and space

Wrapped every `logger.*` call in `srs/persistence.py`, `srs/runtime.py`,
`srs/pipeline.py`, and `srs/cli.py` that interpolates a user-controlled
value. Specifically:
- `task_id`, `task.kind` (runtime.py + pipeline.py + cli.py)
- `snapshot_id`, `snap_path`, `fpath`, `p` (persistence.py + runtime.py)
- `home` path (runtime.py + cli.py)
- Exception messages `e` tied to user-controlled values (everywhere)
- `raw` SRS_HOME value (persistence.py `default_path`)

### Fix 2 — `default_path()` validates SRS_HOME (R17.11)

```python
def default_path() -> Path:
    raw = os.environ.get("SRS_HOME")
    if raw:
        try:
            resolved = Path(raw).resolve()
        except (OSError, RuntimeError) as e:
            logger.warning("SRS_HOME=%s could not be resolved (%s); using default",
                           _safe_log_value(raw), e)
            return Path.home() / ".srs" / "snapshots"
        # Reject paths inside system pseudo-filesystems.
        forbidden_prefixes = ("/dev", "/proc", "/sys")
        sp = str(resolved)
        for prefix in forbidden_prefixes:
            if sp == prefix or sp.startswith(prefix + "/"):
                logger.warning(
                    "SRS_HOME=%s resolves to forbidden location %s; using default",
                    _safe_log_value(raw), prefix,
                )
                return Path.home() / ".srs" / "snapshots"
        # If the path already exists, it must be a directory.
        try:
            if resolved.exists() and not resolved.is_dir():
                logger.warning(
                    "SRS_HOME=%s resolves to %s which is not a directory; using default",
                    _safe_log_value(raw), _safe_log_value(resolved),
                )
                return Path.home() / ".srs" / "snapshots"
        except OSError as e:
            logger.warning("SRS_HOME=%s stat failed (%s); using default",
                           _safe_log_value(raw), e)
            return Path.home() / ".srs" / "snapshots"
        return resolved / "snapshots"
    return Path.home() / ".srs" / "snapshots"
```

Validation layers (defense in depth):
1. **Resolve** — `Path(raw).resolve()` canonicalizes the path
   (eliminates `..`, resolves symlinks).
2. **Blocklist** — rejects any path inside `/dev`, `/proc`, or `/sys`.
   `/dev/null`, `/dev/zero`, `/dev/shm`, `/proc/self`, `/proc/self/fd/N`,
   `/sys/kernel`, etc. are all rejected.
3. **Type check** — if the path exists, it must be a directory (rejects
   `SRS_HOME=/etc/passwd` and other regular files).
4. **Stat-failure fallback** — if `stat()` raises (e.g. permission
   denied), fall back to default rather than crashing.

On any rejection, the function **logs a WARNING** and falls back to the
default `~/.srs/snapshots` — the CLI keeps working, the user gets a
visible warning, no exception propagates.

### Fix 3 — `SafeFormatter` class (R16.10)

Added to `srs/persistence.py`:

```python
class SafeFormatter(logging.Formatter):
    """Logging formatter that sanitizes the final message to prevent
    log injection (R17.13, R16.10)."""

    def format(self, record: logging.LogRecord) -> str:
        msg = super().format(record)
        return msg.replace("\n", "\\n").replace("\r", "\\r")
```

This is the **second layer** of defense: even if a value slips past
`_safe_log_value` (e.g. an exception's `__str__` returns a multiline
traceback), the formatted log message stays single-line.

Applied in `srs/cli.py`'s `_configure_logging()`:

```python
formatter = SafeFormatter(
    fmt="%(asctime)s %(levelname)-5s %(name)s: %(message)s",
    datefmt="%H:%M:%S",
)
handler = logging.StreamHandler(stream=sys.stderr)
handler.setFormatter(formatter)
root = logging.getLogger()
root.handlers = [handler]  # replaces any existing handlers
root.setLevel(level)
```

Switched from `logging.basicConfig` to explicit `handlers = [handler]`
so:
- We control the formatter class (`basicConfig` installs a plain
  `logging.Formatter` and has no parameter for a custom class).
- Repeat calls to `main()` (e.g. from tests) don't accumulate duplicate
  handlers — `handlers = [handler]` replaces, `basicConfig` only adds
  if no handlers exist (so the second call's level change is silently
  ignored).

## 5. Security Model

**Threat model**: An attacker who can:
- Supply a `task_id` or `snapshot_id` via the CLI / API,
- Set the `SRS_HOME` environment variable before launching the runtime,
- Write to the snapshots directory (but NOT to `~/.srs/secret_key`).

**Defenses (in order of layering)**:

1. **Input validation** (already in place):
   - `Task.__post_init__` calls `_sanitize_task_id` (R17.9)
   - `task_id` property setter re-sanitizes on mutation (R18 C4)
   - `_sanitize_id` rejects path-traversal characters in `snapshot_id`

2. **Log-side sanitization** (NEW in v7.8):
   - `_safe_log_value()` strips control chars + truncates at every
     logger call site (defense in depth — survives any future bypass
     of the input validator).

3. **Final-message sanitization** (NEW in v7.8):
   - `SafeFormatter` escapes `\n` / `\r` in the formatted log message
     (catches values that slip past `_safe_log_value`, e.g. exception
     `__str__` returning a multiline traceback).

4. **SRS_HOME validation** (NEW in v7.8):
   - `default_path()` resolves and blocklists system pseudo-FS paths
     before returning, so a malicious `SRS_HOME` cannot brick the
     runtime or write to kernel-controlled files.

## 6. What This Does NOT Close

- **R17.6** (inflight files unprotected): closed in a separate v7.8
  fix (inflight HMAC, already present in `save_in_flight` /
  `load_in_flight`).
- **R17.10** (snapshot_id predictable): the snapshot_id is
  `sha256(f"{time_ns()}_{iso_now()}")[:12]` — still based on time alone.
  A future fix should mix in `os.urandom(4)` for collision resistance.
- **R17.12** (RNG predictability): closed in v7.7 via
  `secrets.SystemRandom` for verification when `rng=None`.

## 7. Backward Compatibility

- `_safe_log_value` only sanitizes values that contain control chars;
  normal ASCII task_ids / paths pass through unchanged. Existing log
  output for legitimate users is unaffected.
- `SafeFormatter` only escapes `\n` / `\r`; messages without newlines
  are byte-identical to the previous `logging.Formatter` output.
- `default_path()` still accepts all legitimate paths (tempdirs,
  `~/.srs`, custom `--home`); only `/dev`, `/proc`, `/sys`, and
  non-directory existing paths are rejected. The fallback is the
  default `~/.srs/snapshots`, so no caller breaks.
- The CLI's `_configure_logging` now uses `root.handlers = [handler]`
  instead of `logging.basicConfig`. This is functionally equivalent
  for the first call; for repeat calls (e.g. tests that invoke
  `main()` twice), the new behavior is BETTER (no duplicate handlers,
  so the level change on the second call is honored).
