# v6.44 — Formal Mathematical Definition of "Computational Primitive"

## Preamble: The Circularity Problem in v6.42

The v6.43 audit (see `/home/z/my-project/download/v6_theory/v6.43_ADVERSARIAL_AUDIT.md`, §1.1 and §2.4) found that v6.42's definition of *primitive* is circular:

> v6.42 defines a primitive as a "mechanism that (a) yields an asymptotic advantage on at least one resource axis, (b) is irreducible to the other primitives under polynomial-time reduction, and (c) is physically realizable."

Clause (b) is the killer: a primitive is defined in terms of "the other primitives", but the set of primitives is exactly what is being defined. This is a recursive definition with no base case. The set {C, A, S, V, E} in v6.42 is therefore picked by **convention**, not by derivation. There is no formal object against which "Π₁ ≤ Π₂" can be tested as a mathematical proposition.

The mission of this document is to repair that defect. We propose three candidate formal definitions of *computational primitive*, choose the strongest, and under that choice give formal definitions of reducibility (Π₁ ≤ Π₂), equivalence (Π₁ ≡ Π₂), and strict weakness (Π₁ < Π₂). We then state the Closure Theorem in a bulletproof, falsifiable, assumption-explicit form.

**Notation.** We use plain-text LaTeX-style math (`\forall`, `\exists`, `\leq`, `\subseteq`, etc.). All claims are tagged `[PROVEN]`, `[CONDITIONAL ON X]`, `[UNKNOWN]`, or `[HYPOTHESIZED]`. Standard results are cited inline. We work over the alphabet `{0,1}`; languages are subsets of `{0,1}*`. We write `P`, `NP`, `L`, `NL`, `NC`, `PSPACE`, `EXP`, `BPP`, `BQP`, `P/poly` for the standard complexity classes (see Arora-Barak, *Computational Complexity: A Modern Approach*, 2009).

## Part 1 — Three Candidate Formal Definitions

We consider three families of formal objects that could serve as a *primitive*:
- **Candidate A (Complexity-Class):** a primitive is a complexity class together with a canonical resource measure.
- **Candidate B (Circuit-Family):** a primitive is a uniform circuit class with a structural restriction.
- **Candidate C (Oracle-Reduction):** a primitive is an oracle with a specific access model.

For each candidate we give (i) the formal definition, (ii) the instantiation of {C, A, S, V, E}, (iii) a proof of non-circularity, and (iv) the formal meaning of `Π₁ ≤ Π₂`.

---

### Candidate A — Complexity-Class Definition

**Definition A.1 (Primitive as complexity class).** A *computational primitive* is a pair `Π = (C_Π, ρ_Π)` where:
- `C_Π ⊆ {0,1}*` is a complexity class (a set of languages decidable under some resource bound),
- `ρ_Π: ℕ → ℕ` is a *canonical resource bound function* that defines `C_Π` operationally, i.e., `C_Π = { L ⊆ {0,1}* : L is decidable by a TM (or circuit family) respecting ρ_Π }`.

We say an algorithm `A` *uses primitive `Π`* iff `A` is a decider for some `L ∈ C_Π` and `A`'s resource usage on inputs of length `n` is `O(ρ_Π(n))`.

**Instantiation A.2 (The five primitives as complexity classes).** We instantiate the v6.42 conceptual primitives as standard complexity classes:

| Primitive | Conceptual name (v6.42) | Formal class `C_Π` | Canonical resource `ρ_Π` |
|-----------|-------------------------|---------------------|---------------------------|
| `E`       | Execution               | `P`                 | time `≤ n^k` for some `k` |
| `C`       | Compression             | `L = DSPACE(log n)` | space `≤ O(log n)`        |
| `S`       | Scheduling              | `NC`                | depth `≤ (log n)^k`, size `≤ n^k` |
| `A`       | Adaptivity              | `P^{NP}[log] = Θ_2^P` | adaptive queries `≤ O(log n)` to NP oracle |
| `V`       | Verification            | `NP = PCP[O(log n), O(1)]` | verifier queries `≤ O(1)`, randomness `≤ O(log n)` |

**Justification of instantiation:**

- `E := P`. Execution is the baseline: a Turing machine running in polynomial time. This is the standard formalization of "ordinary efficient computation." `[PROVEN]` `P` is a complexity class.

- `C := L` (deterministic logspace). The v6.42 notion of "compression" is "shrinking state / representation below the input size." Deterministic logspace captures exactly algorithms that use `O(log n)` workspace on inputs of length `n`, i.e., sublinear (specifically logarithmic) state. `[PROVEN]` `L` is a complexity class; `[PROVEN]` `L ⊆ P` (a logspace TM runs in polynomial time, since it has at most polynomially many configurations).

  *Caveat.* v6.42 also discussed Kolmogorov complexity `K(f)` as the ultimate lower bound on compression. `K(f)` is `[PROVEN]` uncomputable (Li-Vitányi, *An Introduction to Kolmogorov Complexity and Its Applications*, Theorem 2.3.2). We therefore use `L` (the computable approximation) as the formal class for `C`. The information-theoretic lower bound `K(f)` is acknowledged but cannot be the primitive itself because it has no decider.

- `S := NC` (Nick's Class). Scheduling in v6.42 is about parallel time: turning a long sequential computation into many short parallel ones. `NC = ⋃_k NC^k = ⋃_k { languages decidable by polynomial-size, `O((log n)^k)`-depth circuits }` is the standard formalization of "efficiently parallelizable" (Borodin 1977; Cook 1979; Pippenger 1979). `[PROVEN]` `NC ⊆ P`.

- `A := P^{NP}[log]`. The v6.42 primitive `A` is "adaptive query complexity" — this was already shown (v6.41) to be isomorphic to Babai-Frankl adaptive query complexity (Babai-Frankl-Simon 1986, *Complexity Classes in Communication Complexity Theory*). To make this a *complexity class* we instantiate `A` as `P^{NP}[log]`, the class of languages decidable in polynomial time with `O(log n)` adaptive queries to an `NP` oracle (equivalently, `Θ_2^P`, the second level of the polynomial hierarchy in the theta operator form; see Hemachandra 1989, Wagner 1990). This captures the essential feature of adaptivity: the `i`-th query depends on the answers to queries `1, ..., i-1`. `[PROVEN]` `P^{NP}[log]` is a complexity class. `[CONDITIONAL ON PH being non-trivial]` `P ⊆ P^{NP}[log] ⊆ P^{NP}`.

  *Caveat.* `A` does not fit as cleanly into the standard hierarchy as `E, C, S, V` do. This is a feature, not a bug: it reflects that adaptivity is genuinely a query-complexity notion, not a time/space/depth notion, and standard complexity theory has fewer tools for query classes. This is the same observation made in v6.41 (M2 destruction analysis): adaptive query complexity is its own framework.

- `V := NP`. The v6.42 primitive `V` is "verification" via probabilistic checking. By the **PCP Theorem** (Arora-Lund-Motwani-Sudan-Szegedy 1998, *Proof Verification and the Hardness of Approximation Problems*; also Arora-Safra 1998), `NP = PCP[O(log n), O(1)]`: every `NP` language has a probabilistically checkable proof with `O(log n)` random bits and `O(1)` verifier queries. So the "class of languages admitting PCP verification" is exactly `NP`. `[PROVEN]` `PCP[O(log n), O(1)] = NP`.

  *Important limitation.* v6.42 conflated PCP-verification with IP-verification. The `IP = PSPACE` theorem (Shamir 1992) shows that interactive proofs with an *unbounded* prover capture `PSPACE`. The v6.43 audit (§3.4) correctly noted that IP is strictly stronger than `NP` (since `NP ⊆ PSPACE`, with equality open). We therefore restrict `V` to PCP-style (static, non-interactive) verification, which gives `V := NP`. This is `[CONDITIONAL ON A9]`: no unbounded provers are allowed.

**Non-circularity proof (Candidate A).** [PROVEN] The definition of each primitive references only a standard complexity class defined by an independent resource bound:
- `E` references time
- `C` references space
- `S` references depth (parallel time)
- `A` references oracle queries (adaptive)
- `V` references proof length (PCP queries)

No primitive is defined in terms of another. The set `{C, A, S, V, E}` is therefore well-defined as a 5-tuple of formal objects `(L, P^{NP}[log], NC, NP, P)`. The circularity defect of v6.42 (clause b) is eliminated. ∎

**Reducibility under Candidate A.** `Π₁ ≤ Π₂` iff `C_{Π₁} ⊆ C_{Π₂}` (class inclusion). `Π₁ ≡ Π₂` iff `C_{Π₁} = C_{Π₂}`. `Π₁ < Π₂` iff `C_{Π₁} ⊊ C_{Π₂}` (strict inclusion). These are well-defined mathematical propositions with truth values.

### Candidate B — Circuit-Family Definition

**Definition B.1 (Primitive as circuit class).** A *computational primitive* is a triple `Π = (G_Π, R_Π, U_Π)` where:
- `G_Π` is a set of allowed gate types (extending the standard Boolean basis `B_0 = {AND, OR, NOT, FANOUT}`),
- `R_Π` is a structural restriction on circuits (e.g., depth `≤ d(n)`, width `≤ w(n)`, size `≤ s(n)`, gate-type count `≤ c(n)`),
- `U_Π ∈ {uniform, non-uniform}` specifies uniformity.

The class `C_Π` is the set of languages `L` such that `L` is decided by a `U_Π`-uniform family `{C_n}` of polynomial-size circuits over `G_Π` respecting `R_Π`.

**Instantiation B.2 (The five primitives as circuit classes).**

| Primitive | Gate basis `G_Π` | Structural restriction `R_Π` | Uniformity | Standard name |
|-----------|-------------------|-------------------------------|------------|----------------|
| `E`       | `B_0`             | size `≤ n^k`                   | DLOGTIME-uniform | `P` |
| `C`       | `B_0`             | width `≤ (log n)^k` (bounded-width branching programs) | logspace-uniform | `SC` (Steve's Class) ⊇ `L` |
| `S`       | `B_0`             | depth `≤ (log n)^k`, size `≤ n^k` | DLOGTIME-uniform | `NC` |
| `A`       | `B_0 ∪ {Q_ adaptive}` | `≤ O(log n)` adaptive query gates | poly-time uniform | adaptive query class |
| `V`       | `B_0 ∪ {PCP-check}` | `≤ O(1)` PCP-check gates, `≤ O(log n)` random bits | poly-time uniform | `PCP[log n, O(1)] = NP` |

Here `Q_adaptive` is a gate that takes a circuit-state and a query, queries an oracle for some fixed `NP` language (e.g., SAT), and outputs the response; the circuit may condition subsequent gates on the response. `PCP-check` is a gate implementing a constant-query probabilistic verifier for some fixed `NP`-complete relation.

**Non-circularity proof (Candidate B).** [PROVEN] Each primitive is defined by a structural restriction on circuits (a syntactic property of the circuit family). No primitive is defined by reference to another primitive. ∎

**Reducibility under Candidate B.** Same as Candidate A: `Π₁ ≤ Π₂` iff `C_{Π₁} ⊆ C_{Π₂}` (class inclusion of the corresponding circuit classes).

**Trade-off vs Candidate A.** Candidate B is more unified (everything is circuits) but the gate types `Q_adaptive` and `PCP-check` are non-standard and require careful definition. The class `SC` (Steve's Class, `DSPACE(log n) ∩ P`) is a closer formalization of "compression via bounded-width circuits" than `L` alone, but `SC` is less commonly used in the literature.

### Candidate C — Oracle-Reduction Definition

**Definition C.1 (Primitive as oracle).** A *computational primitive* is a triple `Π = (O_Π, A_Π, c_Π)` where:
- `O_Π: {0,1}* → {0,1}*` is an oracle (a total function),
- `A_Π ∈ {adaptive, non-adaptive, parallel}` specifies the access model,
- `c_Π: ℕ → ℕ` is the per-query cost (or the bound on the number of queries as a function of input length).

The class `C_Π` is the set of languages decidable by a polynomial-time Turing machine with oracle access `(A_Π, c_Π)` to `O_Π`.

**Instantiation C.2 (The five primitives as oracles).**

| Primitive | Oracle `O_Π` | Access model | Query bound | Resulting class |
|-----------|--------------|--------------|-------------|-----------------|
| `E`       | trivial (returns `0`) | — | 0 | `P` |
| `C`       | compression oracle: `O_C(x) = LZ(x)` (a computable compressor, e.g., Lempel-Ziv) | non-adaptive | unbounded (but counted in space) | `P^{O_C}` |
| `A`       | adaptive query oracle: `O_A(state, q) = f(q)` for an `NP` function `f` | adaptive | `≤ O(log n)` | `P^{NP}[log] = Θ_2^P` |
| `S`       | scheduling oracle: `O_S(DAG) = optimal parallel schedule` | non-adaptive | unbounded | `P^{O_S}` |
| `V`       | verification oracle: `O_V(x, π) = 1` iff `π` is a valid PCP proof of `x ∈ L` | non-adaptive | `≤ O(1)` queries to `O_V`, `≤ O(log n)` random bits | `NP` |

**Non-circularity proof (Candidate C).** [PROVEN] Each primitive is defined by an oracle and an access model. The oracles are independent mathematical objects (total functions). No primitive is defined in terms of another primitive. ∎

**Reducibility under Candidate C.** `Π₁ ≤ Π₂` iff `O_{Π₁}` is Turing-reducible to `O_{Π₂}`, i.e., `O_{Π₁} ∈ FP^{O_{Π₂}}` (computable in polynomial time with oracle `O_{Π₂}`). This is the standard notion of oracle reducibility (Turing 1939; Rogers 1967; Baker-Gill-Solovay 1975, *Relativizations of the P =? NP Question*).

**Trade-off vs Candidates A and B.** Candidate C is closest to engineering intuition (a primitive is "something you call"), and oracle reducibility is the most thoroughly studied reducibility notion in complexity theory. The downside is that oracles don't capture the *intrinsic* property of the algorithm — they're external. Also, by Baker-Gill-Solovay (1975), oracle results may not transfer to the unrelativized setting; an oracle separation `O_1 ≰ O_2` does not imply the unrelativized separation.

## Part 2 — Choose the Strongest Candidate

We choose **Candidate A (Complexity-Class Definition)** as the formal definition of primitive. Reasons:

**Reason 1: Best alignment with standard complexity theory.** Candidate A reduces to standard complexity classes (`P`, `L`, `NC`, `NP`, `P^{NP}[log]`) for four of the five primitives. Only `A` requires the slightly non-standard `Θ_2^P`. This means that the reducibility claims `Π₁ ≤ Π₂` become standard complexity-class inclusion questions, which have been studied for decades.

**Reason 2: Reducibility is class inclusion.** Class inclusion is a well-defined mathematical relation with a truth value. `Π₁ ≤ Π₂` iff `C_{Π₁} ⊆ C_{Π₂}`. This is the same relation used in the standard complexity-class chart (`NC ⊆ L ⊆ NL ⊆ P ⊆ NP ⊆ PSPACE`), and the truth or falsity of each inclusion is a known open problem.

**Reason 3: Separation proofs become circuit lower bounds.** Showing `Π₁ ≰ Π₂` (i.e., `C_{Π₁} ⊄ C_{Π₂}`) is exactly a circuit lower bound, which is the gold standard of complexity-theoretic separation. We can leverage decades of known results: time-hierarchy (Hartmanis-Stearns 1965), space-hierarchy (Hartmanis et al. 1965), `AC^0 ⊊ NC^1` (Furst-Saxe-Sipser 1984; Ajtai 1983), `AC^0[p] ⊊ NC^1` for prime `p` (Razborov 1987; Smolensky 1987).

**Reason 4: Non-circularity is provable and clean.** Each primitive is a single complexity class defined by an independent resource bound. No reference to "other primitives" is needed.

**Reason 5: The framework is falsifiable without resolving open conjectures.** Under Candidate A, the Closure Theorem (Part 5) decomposes into a set of class-inclusion claims, each of which is either `[PROVEN]`, `[CONDITIONAL ON open conjecture]`, or `[UNKNOWN]`. This is exactly the granularity that allows the theorem to be a *scientific claim* (falsifiable per Popper) rather than a *metaphysical claim* (unfalsifiable per the v6.43 audit §1.4).

**Trade-offs acknowledged.**
- Candidate A treats primitives as classes of problems, but the v6.42 engineering intuition is that primitives are *mechanisms* (properties of algorithms). This is a category shift: we are formalizing "the class of problems for which mechanism Π yields an asymptotic advantage" rather than "mechanism Π itself." This is the standard complexity-theoretic move and is necessary for the reducibility relation to have a truth value. `[HYPOTHESIZED]` this captures the engineering intuition adequately.
- `A` does not fit as cleanly as the other four. This is acknowledged in §1.A.2 above and is consistent with v6.41's finding that adaptivity is its own framework.
- We do not use Candidate B (more unified, but non-standard gates) or Candidate C (oracles are external, Baker-Gill-Solovay caveat). Both are valid alternatives; we mention them for completeness.

## Part 3 — Formal Reducibility Relation

Under Candidate A, we define:

**Definition 3.1 (Reducibility).** For two primitives `Π₁, Π₂`, we write `Π₁ ≤ Π₂` and say "*`Π₁` reduces to `Π₂`*" iff `C_{Π₁} ⊆ C_{Π₂}` (class inclusion).

**Definition 3.2 (Equivalence).** `Π₁ ≡ Π₂` iff `Π₁ ≤ Π₂` and `Π₂ ≤ Π₁` (i.e., `C_{Π₁} = C_{Π₂}`).

**Definition 3.3 (Strict weakness).** `Π₁ < Π₂` iff `Π₁ ≤ Π₂` and `Π₁ ≢ Π₂` (i.e., `C_{Π₁} ⊊ C_{Π₂}`, strict inclusion).

**Definition 3.4 (Incomparability).** `Π₁ ⊥ Π₂` iff neither `Π₁ ≤ Π₂` nor `Π₂ ≤ Π₁` (i.e., `C_{Π₁} ⊄ C_{Π₂}` and `C_{Π₂} ⊄ C_{Π₁}`).

**Definition 3.5 (Separation).** `Π₁ ≰ Π₂` iff `¬(Π₁ ≤ Π₂)`, i.e., `C_{Π₁} ⊄ C_{Π₂}`.

**Proposition 3.6 (Well-definedness).** [PROVEN] Definitions 3.1–3.5 yield a partial preorder on the set of primitives (with `≡` being the induced equivalence). The relations are well-defined mathematical propositions with truth values, in the standard model of computation.

*Proof.* Class inclusion `⊆` is a well-defined relation on the powerset of `{0,1}*`. Definitions 3.1–3.5 are direct translations. The composition `≤` is reflexive and transitive (since `⊆` is). ∎

**Remark 3.7 (Truth values are mostly open).** Under Candidate A, the truth values of `Π₁ ≤ Π₂` for pairs of distinct primitives in `{C, A, S, V, E}` are largely *unknown* — they coincide with open complexity-theoretic conjectures (`P vs L`, `P vs NC`, `P vs NP`, `L vs NC`, `NP vs NC`, etc.). This is the central honest finding of v6.44: **the formalization reveals that v6.42's "mutual irreducibility" claim cannot be proved without resolving multiple open conjectures.** This is documented in Part 4 below.

## Part 4 — Separation Examples for All Pairs

We instantiate the five primitives as in §1.A.2: `E = P`, `C = L`, `S = NC`, `A = P^{NP}[log] = Θ_2^P`, `V = NP`. There are `5 × 4 = 20` ordered pairs of distinct primitives. We list each pair `(Π₁, Π₂)` and state whether `Π₁ ≤ Π₂` or `Π₁ ≰ Π₂` (or whether the answer is unknown).

### 4.1 Pairs involving `E = P`

**(E, S):** `E ≤ S`? This asks `P ⊆ NC`. *Open.* The standard conjecture is `P ⊋ NC` (some `P`-complete problems, like Circuit Value Problem, are believed not in `NC`). Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `E ≰ S` conditional on `P ⊋ NC`. No proof known. (Greenlaw-Hoover-Ruzzo, *Limits to Parallel Computation*, 1995, survey `P`-completeness.)

**(S, E):** `S ≤ E`? This asks `NC ⊆ P`. `[PROVEN]` Yes. A polynomial-size, polylog-depth circuit can be simulated in polynomial time by a TM (just evaluate the circuit level by level). Tag: `[PROVEN]`.

**(E, C):** `E ≤ C`? This asks `P ⊆ L`. *Open.* The standard conjecture is `P ⊋ L` (e.g., `SL = L` was open until Reingold 2005; `P`-complete problems like Circuit Value are believed outside `L`). Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `E ≰ C` conditional on `P ⊋ L`. No proof known.

**(C, E):** `C ≤ E`? This asks `L ⊆ P`. `[PROVEN]` Yes. A logspace TM has polynomially many configurations, so it halts in polynomial time. Tag: `[PROVEN]`.

**(E, V):** `E ≤ V`? This asks `P ⊆ NP`. `[PROVEN]` Yes. Every deterministic poly-time computation is a special case of a nondeterministic one (the verifier ignores the proof). Tag: `[PROVEN]`.

**(V, E):** `V ≤ E`? This asks `NP ⊆ P`, i.e., `P = NP`. *Open.* The standard conjecture is `P ⊋ NP` (Cook-Levin 1971; Karp 1972). Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `V ≰ E` conditional on `P ≠ NP`. No proof known.

**(E, A):** `E ≤ A`? This asks `P ⊆ P^{NP}[log]`. `[PROVEN]` Yes. A poly-time computation can be simulated with zero queries to the oracle, so it is trivially in `P^{NP}[log]`. Tag: `[PROVEN]`.

**(A, E):** `A ≤ E`? This asks `P^{NP}[log] ⊆ P`, i.e., `P = Θ_2^P`. *Open.* Since `P ⊆ NP ∩ coNP ⊆ Θ_2^P ⊆ P^{NP}`, the question `P = Θ_2^P` lies between `P = NP ∩ coNP` and `P = P^{NP}`. *Open.* Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `A ≰ E` conditional on `P ⊊ Θ_2^P` (which is implied by `P ⊊ NP`).

### 4.2 Pairs involving `C = L`

**(C, S):** `C ≤ S`? This asks `L ⊆ NC`. *Open.* Known: `NC^1 ⊆ L ⊆ NC^2` (Borodin et al. 1982; see Arora-Barak §6). So `L` lies between `NC^1` and `NC^2`; whether `L = NC` is open. Tag: `[UNKNOWN]`.

**(S, C):** `S ≤ C`? This asks `NC ⊆ L`. *Open.* Same reason: `NC^1 ⊆ L` is proven; `NC^2 ⊆ L` is open. Tag: `[UNKNOWN]`.

**(C, V):** `C ≤ V`? This asks `L ⊆ NP`. `[PROVEN]` Yes. `L ⊆ P ⊆ NP`. Tag: `[PROVEN]`.

**(V, C):** `V ≤ C`? This asks `NP ⊆ L`. *Open.* Believed false (since `P ⊆ NP` and `P` is believed to extend beyond `L`). Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `V ≰ C` conditional on `NP ⊄ L`.

**(C, A):** `C ≤ A`? This asks `L ⊆ P^{NP}[log]`. `[PROVEN]` Yes. `L ⊆ P ⊆ P^{NP}[log]`. Tag: `[PROVEN]`.

**(A, C):** `A ≤ C`? This asks `P^{NP}[log] ⊆ L`. *Open.* Believed false. Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `A ≰ C` conditional on `P^{NP}[log] ⊄ L` (implied by `NP ⊄ L`).

### 4.3 Pairs involving `S = NC`

**(S, V):** `S ≤ V`? This asks `NC ⊆ NP`. `[PROVEN]` Yes. `NC ⊆ P ⊆ NP`. Tag: `[PROVEN]`.

**(V, S):** `V ≤ S`? This asks `NP ⊆ NC`. *Open.* Believed false. Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `V ≰ S` conditional on `NP ⊄ NC`.

**(S, A):** `S ≤ A`? This asks `NC ⊆ P^{NP}[log]`. `[PROVEN]` Yes. `NC ⊆ P ⊆ P^{NP}[log]`. Tag: `[PROVEN]`.

**(A, S):** `A ≤ S`? This asks `P^{NP}[log] ⊆ NC`. *Open.* Believed false. Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `A ≰ S` conditional on `P^{NP}[log] ⊄ NC`.

### 4.4 Pairs involving `V = NP`

**(V, A):** `V ≤ A`? This asks `NP ⊆ P^{NP}[log]`. *Open.* The standard `P^{NP}[log]` is `Θ_2^P`, which lies between `NP ∩ coNP` and `Δ_2^P = P^{NP}`. Whether `NP ⊆ Θ_2^P` is open; the inclusion `NP ⊆ Θ_2^P` would follow from `NP = coNP` (open). Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `V ≰ A` conditional on `NP ⊄ Θ_2^P`.

**(A, V):** `A ≤ V`? This asks `P^{NP}[log] ⊆ NP`. *Open.* `P^{NP}[log]` contains both `NP` and `coNP` (a log-query NP machine can decide both `NP` and `coNP` languages). So `P^{NP}[log] ⊆ NP` would imply `coNP ⊆ NP`, hence `NP = coNP` (open). Tag: `[UNKNOWN]`. `[HYPOTHESIZED]` `A ≰ V` conditional on `NP ≠ coNP`.

### 4.6 Honest Summary of Part 4
