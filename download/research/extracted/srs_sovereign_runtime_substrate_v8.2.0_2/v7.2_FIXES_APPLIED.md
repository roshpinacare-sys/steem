## Fix 1: Pipeline State Passing (R1.1, R1.2, R4.5)

**File:** `srs/pipeline.py`

**Root cause:** Stages received only `(task, rng, **kwargs)` and returned
independent dicts. No shared state → V couldn't read E/A's candidate →
runtime passed `target_idx` as candidate → V always returned True (R1.1).

**Fix:**
- Added `PipelineState` dataclass (lines 30-50) carrying `answer`,
  `correct`, `verified`, `queries_made`, `transcript`, `alive_set`,
  `candidate`, `confident`, plus accounting fields.
- Changed all stage signatures to `(task, state, rng, effective_budget=None, **kw)` (lines 100-260).
- Stages MUTATE state instead of returning dicts.
- `Pipeline.execute` (lines 60-95) creates one `PipelineState`, passes it
  to every stage, then converts to `Result`.
- `verification_stage` (lines 195-240) reads `state.candidate` (set by
  E/A/Adv), NEVER `task.payload["target_idx"]`. If `state.candidate` is
  wrong, V makes k probes and detects the mismatch → `verified=False`.

**Validation:**
```

  queries=3, verification_calls=2
  PASS: V detected wrong candidate (no longer theatre)
```

## Fix 4: Advice Integrity (R3.2)

**Files:** `srs/persistence.py` (lines 60-75, 115-145), `srs/types.py` (lines 60-75)

**Root cause:** Snapshots loaded advice tables blindly. A tampered snapshot
injecting `{h_hash: 999}` would be trusted, producing wrong answers.

**Fix:**
- Added `_compute_advice_hash` (persistence.py:62) — SHA-256 of
  `json.dumps(advice_table, sort_keys=True)`.
- `save` (persistence.py:90) computes and stores `advice_hash` alongside
  the advice table.
- `load_latest` (persistence.py:128) recomputes the hash on load; if it
  mismatches, logs a warning and discards the advice table (replaces with
  `{}`).
- `Snapshot` dataclass (types.py:67) gained `advice_hash: Optional[str] = None`.
- `Snapshot.from_dict` (types.py:78) now filters unknown keys (robustness
  fix — prevents TypeError on extra fields).

**Validation:**
```

  (log: "advice hash mismatch (stored=4be281edc378, actual=42d1d8dedda3); discarding advice")
```

## Fix 5: Resume Actually Works (R1.3)

**File:** `srs/runtime.py` (lines 70-90), `srs/persistence.py` (lines 160-220)

**Root cause:** `execute(resume=True)` set `task._resumed_from` — a private
attribute no stage ever read. The pipeline ran from scratch.

**Fix:**
- `runtime.py:72-87`: when `resume=True` and in-flight state exists,
  load `queries_made` and `rng_state`.
- Restore the RNG via `rng.setstate(persistence._deserialize_rng_state(rng_state))`
  so the RNG continues from where it left off.
- Pass `skip_queries` to `pipe.execute(task, rng, skip_queries=skip_queries)`,
  which reduces the effective budget by `skip_queries` (line 75 of pipeline.py).
- Added `_serialize_rng_state` / `_deserialize_rng_state` helpers
  (persistence.py:67-87) that convert `rng.getstate()` tuples to JSON-safe
  lists and back. The old code did `str(rng.getstate())` which could not be
  restored.
- `save_in_flight` now stores the rng state as a proper serialized list,
  not a string.

**Note:** This is a partial resume — the alive set is not reconstructed.
The rng state is restored (so the same queries aren't repeated) and the
budget is reduced (so fewer queries are made). A full resume would require
saving the alive set after each query, which is a larger change.

**Validation:** Self-test `srs.runtime` passes; `skip_queries` reduces
effective budget; rng state round-trips through JSON (persistence self-test).

## Fix 6: Try/Finally for In-Flight Cleanup (R1.5)

**File:** `srs/runtime.py` (lines 140-160)

**Root cause:** No try/finally around `pipe.execute`. A single raised
primitive leaked `inflight_*.json` forever (no cleanup, no resume path).

**Fix:**
```python
persistence.save_in_flight(...)
success = False
try:
    r = pipe.execute(task, rng, skip_queries=skip_queries)
    # ... post-processing ...
    success = True
finally:
    # R1.5 fix: clear in-flight state only on success;
    # on exception, preserve it so the user can resume.
    if success:
        persistence.clear_in_flight(self.home, task.task_id)
```

On exception, `success` remains `False`, the `finally` block skips the
clear, and the in-flight state is preserved for resume.

**Validation:**
```
R1.5 fix: in-flight preserved after crash (found=True)
```

## Fix 7: Planner Matches Pipeline (R4.5, R1.4)

**File:** `srs/planner.py` (lines 60-140, 175-200)

**Root cause:** Planner assumed primitives "replace" each other (A replaces
E, Adv replaces E+A+V). Pipeline ran them independently and summed queries.
Estimate was 3.7× off.

**Fix:**
- `estimate_cost` (planner.py:62) now checks `short_circuit = "Adv" in
  primitives and advice_available` first. If true, returns `queries=0`
  immediately (matches pipeline's advice-hit short-circuit).
- For non-short-circuit sets: "A" sets `queries = log2(N)` (A replaces E),
  "V" adds `verify_budget` on top. No double-counting.
- Candidate enumeration (planner.py:185) drops E when A is present
  (`["A", "C", "V"]` instead of `["E", "C", "A", "V"]`) and puts Adv
  first (`["Adv", "A", "C", "V"]`).
- Unknown task kinds now fall back to `"queries"` axis (was `"time"` →
  AttributeError). Lenient by design.

**Validation:**
```
Case 1 (no advice): planner=8, actual=8, match=True   (log2(256)=8)
Case 2 (advice):    planner=0, actual=0, match=True   (short-circuit)
R4.5 PASS: planner estimate matches pipeline actual within 10%
```
