## 5. Architectural Notes

### Lock ordering (R6.14)

A single coarse `threading.RLock` (`_state_lock`) protects
`primitive_stats`, `execution_history`, `last_snapshot`, and the
advice-table reference. This deliberately trades peak concurrency
for simplicity (the critical section is ~10 dict ops, not I/O).
Different `task_id`s parallelize via the per-task `_task_locks`
dict. Documented inline at `runtime.py:79-83`.

### Atomicity layering

Two independent atomicity guarantees stack:
1. **In-process:** `_state_lock` ensures consistent in-memory snapshots.
2. **On-disk:** `_atomic_write_json` ensures readers never see a
   partial file (POSIX `os.replace` is atomic).

A third guarantee (cross-process file locking via `fcntl.flock`) was
NOT added in v7.3 — it's a HIGH-priority item for v7.4 (R6.12).
Without it, two PROCESSES sharing `~/.srs/` can still orphan each
other's snapshots (though they can no longer corrupt them).

### Defense in depth

`n` is capped at three layers:
1. `argparse` accepts any int (defensive: lets us give a helpful error).
2. `cmd_execute` checks `n > MAX_N` and exits 1 with a message.
3. `Task.__post_init__` checks `len(payload["hypotheses"]) > MAX_HYPOTHESES`.

A malicious Python-API caller can bypass (1) and (2) but not (3).
