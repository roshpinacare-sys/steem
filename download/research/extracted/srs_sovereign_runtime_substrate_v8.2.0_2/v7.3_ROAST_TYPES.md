**Agent:** R8 (Type Safety & Static Analysis Roaster)
**Target:** `/home/z/my-project/download/srs/` — 17 Python files, ~2,536 LOC

## 1. Executive Summary

The v7.2 SRS Runtime is **structurally sound but type-systemically bankrupt**. The authors have clearly internalized the *shape* of modern Python typing (PEP 484 annotations, `from __future__ import annotations`, `Optional[...]`, `Dict[str, Any]` everywhere), but they treat the type system as documentation rather than as a contract. The result is a codebase that *looks* typed but where the type checker is systematically silenced — either by `Any`, by missing functions, or by structural holes that no checker could ever cross.

**Headline numbers (real, not estimated):**

| Tool | Errors | Notes |
|---|---|---|
| `mypy --ignore-missing-imports` | **15 errors in 6 files** | Checked 17 source files |
| `ruff check` | **176 errors (134 auto-fixable)** | 12 distinct rule categories |

**Type safety score: 4 / 10.**

The score is bounded above by three structural failures: (a) `default_path()` is *called* in 4 places but *never defined anywhere* — `Runtime()` with no arguments crashes immediately with `AttributeError`, and the type checker caught it 4 times while no human reviewer did; (b) `task.kind: str` accepts any string silently — a typo like `"idenitfy"` runs without complaint and silently falls back to the `[["E"]]` candidate set; (c) `task.payload: Dict[str, Any]` is the de facto schema for the entire runtime and yet is enforced by *nothing* — every pipeline stage reaches into it with `payload["hypotheses"]` / `payload["target_idx"]` and a missing key produces a runtime `KeyError` rather than a static error.

The remainder of this document enumerates 30 findings (R8.1–R8.30), drills into the top 3, and proposes a complete type-system redesign with `Enum`, `TypedDict`, `NewType`, `Protocol`, and `@dataclass(frozen=True)`.

## 4. Top 3 Type Safety Failures (Detailed)

### 4.1 R8.1 — `default_path()` is called 4 times but never defined

**Locations:**
- `srs/persistence.py:98` — `p = _coerce_path(path or default_path())`
- `srs/persistence.py:119` — same
- `srs/persistence.py:158` — same
- `srs/runtime.py:38` — `self.home = persistence._coerce_path(home or persistence.default_path())`

**Evidence the bug is real and live:**

```
$ python3 -c "from srs import Runtime; Runtime()"
AttributeError: module 'srs.persistence' has no attribute 'default_path'
```

**Why this is a type-safety failure and not just a runtime bug:** The function `default_path` is *referenced by name* in 4 places. Python's late binding means the name is looked up at call time, not at parse time, so the bug ships. A statically-typed language (or a Python codebase with `mypy` in CI) would have refused to compile. The v7.2 authors ran neither.

**Why the test suite missed it:** Every `self_test()` in the package constructs `Runtime(home=Path(tmp))` with an explicit `home`. The default-constructor code path is never exercised by any test. This is a coverage hole that type-checking would have closed for free.

**Why it matters for the SRS mission:** The README and the CLI both advertise `Runtime()` as the entry point. The very first line of the very first example in the public API is broken. Anyone who tries to use the runtime without reading the source code (i.e., the intended user) gets an immediate crash.

**Fix:** Add to `persistence.py`:

```python
def default_path() -> Path:
    """Default home directory for SRS snapshots (~/.srs/snapshots)."""
    return Path.home() / ".srs" / "snapshots"
```

And add a regression test:

```python
def test_default_constructor_does_not_crash():
    # Should not raise AttributeError
    rt = Runtime()  # uses default_path()
    assert isinstance(rt.home, Path)
```

### 4.2 R8.3 — `task.kind: str` accepts any string, silently

**Location:** `srs/types.py:20` — `kind: str`

**Evidence (runtime probe):**

```
$ python3 -c "
from srs import Runtime, Task
import tempfile, hashlib
from pathlib import Path
with tempfile.TemporaryDirectory() as tmp:
    rt = Runtime(home=Path(tmp))
    hyps = [hashlib.sha256(f'h{i}'.encode()).digest() for i in range(8)]
    t = Task(kind='idenitfy', payload={'hypotheses': hyps, 'target_idx': 3, 'n_features': 12})
    print('Task constructed with typo kind:', t.kind)
    r = rt.execute(t)
    print('Executed silently, correct=', r.correct)
"
Task constructed with typo kind: idenitfy
Executed silently, correct= True
```

**Why this is dangerous:** `Task(kind="idenitfy", ...)` (note the typo) constructs successfully, plans successfully (planner's `TASK_AXIS.get(task_kind, "queries")` returns the default `"queries"` axis, and the candidate enumeration falls into the `else: candidates = [["E"]]` branch), and executes silently. The user gets a `Result` object back, sees `correct=True`, and never knows their task ran on the wrong code path. There is **no** `ValueError`, no warning, no log line.

The CLI does enforce `choices=["identify", "identify_hard", "search", "verify", "compute"]` at argparse level — but that's only one entry point. Anyone constructing `Task` programmatically (the intended API for embedding the runtime in a larger system, per the README) gets no protection.

**Fix:** Replace the magic strings with an `Enum`:

```python
from enum import Enum

class TaskKind(str, Enum):
    IDENTIFY      = "identify"
    IDENTIFY_HARD = "identify_hard"
    SEARCH        = "search"
    OPTIMIZE      = "optimize"
    VERIFY        = "verify"
    COMPUTE       = "compute"
    STORE         = "store"
    AMORTIZE      = "amortize"

    @classmethod
    def from_str(cls, s: str) -> "TaskKind":
        try:
            return cls(s)
        except ValueError:
            raise ValueError(
                f"Unknown task kind {s!r}. Valid: {[k.value for k in cls]}"
            )

@dataclass(frozen=True)
class Task:
    kind: TaskKind
    payload: IdentifyPayload  # see R8.4
    ...
```

Then `Task(kind="idenitfy", ...)` becomes a **static type error** in mypy and a **runtime `ValueError`** at construction. The planner's `TASK_AXIS` dict can be keyed by `TaskKind` enum members, eliminating the `get(task_kind, "queries")` silent fallback.

### 4.3 R8.4 — `task.payload: Dict[str, Any]` is the de facto schema and is enforced by nothing

**Location:** `srs/types.py:21` — `payload: Dict[str, Any]`

**Evidence (the schema is implicit and scattered):**

Every pipeline stage reaches into `task.payload` with a different subset of keys:

```python
# pipeline.py:112-114  (execution_stage)
hyps = task.payload["hypotheses"]
target = task.payload["target_idx"]
n_features = task.payload.get("n_features", 12)

# pipeline.py:162-164  (adaptivity_stage)  — same keys, different access pattern
hyps = task.payload["hypotheses"]
target = task.payload["target_idx"]
n_features = task.payload.get("n_features", 12)

# pipeline.py:209-211  (verification_stage) — same again

# pipeline.py:265-267  (advice_stage) — same again

# pipeline.py:288-290  (quantum_stage) — same again

# pipeline.py:311     (scheduling_stage) — only uses ["hypotheses"]
```

There are **six** call sites that all expect the same three keys (`hypotheses: List[bytes]`, `target_idx: int`, `n_features: int`), and not one of them is statically checked. A `Task(kind="identify", payload={"hypothesis": hyps, "target": 7})` (singular keys) would pass construction, pass planning, and then `KeyError: 'hypotheses'` at runtime deep inside `execution_stage`. Worse, `target_idx="7"` (string) would silently compare equal to `int(7)` for *most* of the pipeline (because `==` doesn't care about type), then produce wrong results when used as a list index.

The `runtime.py:85` access pattern is even more revealing:

```python
n = len(task.payload.get("hypotheses", [])) if "hypotheses" in task.payload else 64
```

This is a code smell screaming *"I don't trust the type of `payload` and I'm working around it."* The author has hand-rolled runtime type checking inline, badly, when `TypedDict` exists precisely to solve this problem.

**Fix:** Define `TypedDict`s for each task kind's payload:

```python
from typing import TypedDict, Union, List

class IdentifyPayload(TypedDict):
    hypotheses: List[bytes]
    target_idx: int
    n_features: int

class SearchPayload(TypedDict):
    hypotheses: List[bytes]
    target_idx: int
    n_features: int
    marker: bytes          # for Grover

class VerifyPayload(TypedDict):
    hypotheses: List[bytes]
    target_idx: int
    candidate: int
    n_features: int

class ComputePayload(TypedDict):
    code: str
    inputs: List[bytes]

class StorePayload(TypedDict):
    items: List[bytes]
    ttl: int

Payload = Union[IdentifyPayload, SearchPayload, VerifyPayload,
                ComputePayload, StorePayload]

@dataclass(frozen=True)
class Task:
    kind: TaskKind
    payload: Payload        # statically narrowed by `kind`
    ...
```

Mypy can then verify that `execution_stage` (which only runs for `kind=IDENTIFY`) accesses `payload["hypotheses"]` with the right type. Missing keys become static errors. Wrong-type values become static errors. The runtime `task.payload.get("hypotheses", [])` defensive hack can be deleted.

For full type-narrowing by `kind`, consider a `@dataclass` per task kind instead of a `Union` of `TypedDict`s (since `TypedDict` doesn't carry the discriminator). The cleanest pattern is:

```python
@dataclass(frozen=True)
class IdentifyTask:
    kind: Literal[TaskKind.IDENTIFY] = TaskKind.IDENTIFY
    payload: IdentifyPayload
    budget: int = 16
    ...
```

This is the v7.3 redesign proposal in §5.

## 5. Type System Redesign Proposal

### 5.1 Enums (replace magic strings)

```python
# srs/enums.py
from enum import Enum

class TaskKind(str, Enum):
    IDENTIFY      = "identify"
    IDENTIFY_HARD = "identify_hard"
    SEARCH        = "search"
    OPTIMIZE      = "optimize"
    VERIFY        = "verify"
    COMPUTE       = "compute"
    STORE         = "store"
    AMORTIZE      = "amortize"

class PrimitiveKind(str, Enum):
    E   = "E"
    C   = "C"
    A   = "A"
    S   = "S"
    V   = "V"
    ADV = "Adv"
    Q   = "Q"

class PrimaryAxis(str, Enum):
    QUERIES            = "queries"
    WORK_UNITS         = "work_units"
    VERIFICATION_CALLS = "verification_calls"
```

### 5.2 NewTypes (prevent ID mixing)

```python
# srs/ids.py
from typing import NewType

TaskId     = NewType("TaskId", str)
SnapshotId = NewType("SnapshotId", str)
AdviceKey  = NewType("AdviceKey", str)

def new_task_id() -> TaskId:
    import uuid
    return TaskId(uuid.uuid4().hex[:12])

def new_snapshot_id() -> SnapshotId:
    import hashlib, time
    return SnapshotId(hashlib.sha256(str(time.time()).encode()).hexdigest()[:12])
```

After this, `persistence.save_in_flight(home, task.task_id, ...)` and `persistence.save(snap, ...)` where `snap.snapshot_id` is a `SnapshotId` cannot be confused: passing a `TaskId` where a `SnapshotId` is expected is a mypy error.

### 5.5 Frozen dataclasses

```python
@dataclass(frozen=True)
class Task:
    kind: TaskKind
    payload: Payload
    budget: int = 16
    required_primitives: Optional[List[PrimitiveKind]] = None
    task_id: TaskId = field(default_factory=new_task_id)

    def __post_init__(self) -> None:
        if self.budget < 0:
            raise ValueError(f"budget must be >= 0, got {self.budget}")
        # Type-check payload matches kind
        expected = _PAYLOAD_FOR_KIND[self.kind]
        if not isinstance(self.payload, expected):
            raise TypeError(
                f"payload for {self.kind} must be {expected.__name__}, "
                f"got {type(self.payload).__name__}"
            )

    def fingerprint(self) -> str:
        ...

@dataclass(frozen=True)
class Result:
    task_id: TaskId
    answer: Answer
    correct: TriState
    verified: TriState
    primitives_used: Tuple[PrimitiveKind, ...]
    queries: int
    ...
    notes: Mapping[str, Any] = field(default_factory=dict)  # immutable view

    def to_dict(self) -> Dict[str, Any]:
        return asdict(self)

    def with_updates(self, **changes: Any) -> "Result":
        """Return a new Result with the given fields updated (frozen-friendly)."""
        return dataclasses.replace(self, **changes)

@dataclass(frozen=True)
```

### 5.7 Migration plan

1. **Phase 1 (no breaking changes):** Add `mypy` and `ruff` to CI; fix all 15 mypy errors and all 176 ruff issues. Add the missing `default_path()`. Convert all bare `Dict`/`list`/`set` annotations to parameterised forms. This is a one-day job and is purely additive.
2. **Phase 2 (additive types):** Introduce `TaskKind`, `PrimitiveKind`, `PrimaryAxis`, `TriState` enums as parallel types. Add `from_str` constructors. Keep the legacy string APIs working via `__post_init__` coercion.
3. **Phase 3 (NewTypes):** Introduce `TaskId`, `SnapshotId`, `AdviceKey`. Update `Task`, `Snapshot`, persistence functions to use them. Existing string code continues to work (NewType is a no-op at runtime) but mypy starts catching mix-ups.
4. **Phase 4 (TypedDicts):** Introduce `IdentifyPayload`, etc. Update pipeline stages to expect specific payload types. Add a runtime `isinstance` check in `Task.__post_init__` for backward compatibility.
5. **Phase 5 (frozen):** Convert `Task`, `Result`, `Snapshot` to `frozen=True`. Replace all `r.x = y` mutations with `r = r.with_updates(x=y)`. This is the only phase that requires touching call sites.
6. **Phase 6 (Protocols):** Add `Primitive` and `StageFn` protocols. Verify all 7 primitives and all 7 stage functions satisfy them. Add a `mypy --strict` run to CI.

After all six phases, the type-safety score should be **8.5 / 10** (capped because Python's type system can't express dependent types like "if `kind == TaskKind.IDENTIFY` then `payload` is `IdentifyPayload`" without literal-type gymnastics).

## 8. Conclusion

The v7.2 SRS Runtime is a cautionary tale about *annotation theatre*: every public function has a return-type annotation, every dataclass has typed fields, every module has `from __future__ import annotations` at the top — and yet the type system is doing zero work. `Runtime()` crashes on the first line. `Task(kind="idenitfy")` runs silently. `task.payload` is `Dict[str, Any]` and six pipeline stages each reach into it with different keys, hoping for the best. `task_id` and `snapshot_id` are interchangeable strings. `Optional[bool]` makes the CLI exit-code logic depend on the difference between `None` and `False`, which Python's truthiness rules refuse to distinguish.

The fixes are not hard. The `default_path` bug is a 2-line addition. The 134 auto-fixable ruff issues are a single `--fix` invocation. The enums, NewTypes, TypedDicts, Protocols, and frozen dataclasses proposed in §5 are standard Python 3.10+ idioms. What's missing is **discipline**: a CI gate that runs `mypy` and `ruff`, and a refusal to merge code that fails either.

**Without that discipline, v7.2 is type-theatre, not type-safety. Score: 4/10.**
