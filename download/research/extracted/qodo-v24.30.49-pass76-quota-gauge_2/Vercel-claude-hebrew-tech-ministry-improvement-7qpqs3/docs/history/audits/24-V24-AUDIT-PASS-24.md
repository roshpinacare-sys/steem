## Summary

Pass 24 performed a focused security/reliability hardening pass on the GitHub
webhook Cloudflare Worker (`worker/webhook-receiver.js`). With `npx tsc --noEmit`
already clean, the next-highest-leverage opportunity was input validation and
feedback-loop prevention at the system boundary that receives untrusted GitHub
events.

No new dependencies were introduced. All changes are localized to one file
plus a regression-test file.

---

## Primary Engineering Objective

**Harden webhook receiver input validation and self-loop safety.**

### Changes

| Change | Motivation |
|--------|------------|
| `MAX_BODY_BYTES` size cap (5 MiB) | Prevents memory DoS from oversized payloads; returns `413 Payload Too Large` early. |
| `isQodoSender()` / `isQodoApp()` helpers | Detect events generated by Qodo itself to stop feedback loops. |
| Ignore `issue_comment` from Qodo bot | Prevents a Qodo PR comment from re-triggering another webhook action. |
| Ignore `check_suite` events from Qodo app | Prevents a failing Qodo check suite from re-triggering the pipeline indefinitely. |
| `issue_comment` PR-only guard | Only processes comments attached to pull requests (`payload.issue.pull_request`), not regular issues. |
| Default-branch-aware Actions dispatch | The `workflow_dispatch` fallback now uses the repository's `default_branch` instead of hardcoded `main`. |
| Exported helper functions | Enables unit testing of the new boundary helpers. |

## New Environment Bindings (optional)

| Binding | Default | Purpose |
|---------|---------|---------|
| `QODO_BOT_LOGIN` | `qodo` | Login used to identify Qodo bot comments to ignore |
| `QODO_APP_SLUG` | `qodo` | GitHub App slug used to identify Qodo check suites to ignore |

Both are optional. If omitted, the worker falls back to the default values and
still ignores the common `qodo` / `qodo[bot]` identities.
