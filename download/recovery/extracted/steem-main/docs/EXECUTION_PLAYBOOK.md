## 0. שלושה תיקונים מהותיים מהמדידות החיות (חשוב!)

### T1 — ה-feed להמרות אינו "שוק" אלא **מנוהל-חוב** (תיקון לניתוח הקודם)
- מדדנו: כל העדים המובילים מזינים feed **כנה** — 0.043–0.054 SBD/STEEM (ראה טבלת 25 העדים).
- אבל ה-feed הפעיל להמרות (`current_median_history`) = 0.1043 — ונמצאה זהות מספרית מדויקת:
```
feed_פעיל ≈ 9 × SBD_supply / STEEM_supply
         = 9 × 6,455,531 / 556,903,491 = 0.10432   (התאמה 99.99% לנמדד)
```
- זו בדיוק הנוסחה שמחזיקה את יחס החוב על 10.0% (תקרת העצירה). **המשמעות ההנדסית**:
  ערך ההמרה של SBD נקבע מכוח ניהול-החוב, לא לפי העדים. בוט ההמרה חייב לחשב
  את ה-feed הפעיל מהנוסחה (שתי קריאות RPC בלבד) ולא להניח כלום על שוק העדים.
- *(לאימות מול קוד המקור בעת אינטגרציה — הזהות נמדדה אמפירית במדויק רבעוני.)*

### T2 — ארביטראז' ההמרה **לא סגור — הוא שולי-חיובי כרגע** (תיקון)
```
מחיר שוק SBD:        $0.387–0.403   (נמדד)
ערך המרה של 1 SBD:   9.585 STEEM × $0.0434 = $0.416
שולי המרה גולמי:     +3% עד +7.5%  |  מחזור: 3.5 ימים (המרה משולמת בבגרות)
```
- פיזור 365 יום של SBD: מינימום **$0.34**, מקסימום **$0.887**, 26 ימים ≥ $0.80.
- כלומר בעמקי המחיר השוליים מגיעים ל-**+15–20% למחזור**. זה וקטור חי עם טריגר — לא אירועי-נדיר.

### T3 — **השוק הפנימי חי, רדוד ופעור** (גילוי חדש)
```
best ask 0.1009 | best bid 0.0936 SBD/STEEM  → spread 7.5% (!!)
עומק מלא: ask 688,700 SBD / 5.54M STEEM (≈$225K) | bid 3.72M SBD / 45.6M STEEM
cross-rate חוץ (STEEM$/SBD$): 0.1077  → STEEM זול יותר ב-6.6% בשוק הפנימי מאשר בחוץ
```
- שני בוטים נולדו מהמדידה: **פער בין-מקומי** (קנה פנימי → מכור חוץ) ו-**market maker** על spread של 7.5%.

## 1. מטריצת הרשאות מפתחות — יסוד האבטחה

ב-Steem לכל op יש רמת הרשאה. זה מכתיב את הארכיטקטורה: **פיצול לשני בוטים**.

| מפתח | כוח | Ops מורשים (לבוט שלנו) | מדיניות אחזקה |
|---|---|---|---|
| **Posting** | נמוך — לא מזיז כסף | `comment`, `vote`, `custom_json` (posting), `claim_reward_balance` | **חם** — על השרת, ניתן להחלפה מיידית |
| **Active** | גבוה — מזיז כסף | `transfer`, `convert`, `limit_order_*`, `escrow_*`, `delegate_vesting_shares`, `transfer_to/from_savings`, `create_proposal`, `feed_publish`, `witness_update` | **חם-מוגבל** — על שרת מבודד עם תקרת-מסה יומית |
| **Owner** | מלא | שינוי הרשאות, החלפת מפתחות | **קר** — אף פעם לא על שרת |

> כלל ברזל: חשבון-תוכן (posting בלבד) + חשבון-הון (active) נפרדים. חשבון-הון מחזיק
> מינימום מסה — כל עודף זורם ל-SP (שמוגן יחסית: power-down של 13 שבועות נותן
> זמן-תגובה לאירוע חשוד, ובתקדים 2020 הקפאות פגעו בעיקר ביתרות נזילות).

## 2. תשתית ביצוע (משותפת לכל הבוטים)

### 2.1 ערוצי חיבור
```
1) JSON-RPC ישיר (כמו שהשתמשנו במדידות)   ← הבסיס, אפס-תלות
   POST https://api.steemit.com  {"jsonrpc":"2.0","method":"condenser_api.*",...}
2) steem-js (npm steem@0.7.11)             ← חתימה + broadcast + עזרי-פורמט
3) dsteem (0.11.3)                          ← חלופה טיפוסית-חזקה לבוטים
4) SteemConnect                             ← רק לשכבת-משתמש (OAuth), לא לבוטים שלנו
```
- **Failover RPC**: ראשי `api.steemit.com`; גיבויים ציבוריים (לבדוק זמינות שבועית).
  כל בוט קורא גם מ-2 מקורות ומצביע-רוב לפני פעולת-כסף.
- זמינות נמדדה: כל הקריאות שלנו ענו < 1 שנייה.

### 2.2 לולאת בוט גנרית (כל מודול ב-SAOS = זה)
```
כל N דקות:
  state ← קריאות RPC (dynamic_global_properties, feed_history, order_book, rc)
  edge  ← נוסחת הטריגר של הבוט
  אם edge > סף וגם תקרת-מסה לא נחצת:
      בנה פעולה → חתום במפתח המתאים → broadcast → רישום ב-OpLog
  אחרת: רישום "החלטה" בלבד (audit)
```
זה בדיוק `TickContext.emit → kernel` שכבר תוכנן ב-SAOS — במצב live ה-kernel מחתים ומשדר במקום לכתוב ל-SQLite.

### 2.3 פקודות המדידה (הוכחה — אלו בדיוק הקריאות שהריצנו בהצלחה)
```bash
curl -s https://api.steemit.com -X POST -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"condenser_api.get_dynamic_global_properties","params":[],"id":1}'
# + get_feed_history, get_order_book[50], get_witnesses_by_vote["",25],
#   rc_api.find_rc_accounts{accounts:[...]}, list_proposals[[0],5,"by_total_votes",0]
```

## 3. מפרטי בוט — מה נמדד → איך מריצים

### BOT-1 · שכירות SP — הראשון להרצה (P=0.8, ~15% APR מאומת)
| פרמטר | ערך |
|---|---|
| מנגנון | `delegate_vesting_shares` (Active) → מקבל תשלום STEEM/SBD תקופתי ב-`transfer` |
| תשואה שוק | 14.99%–16.99% APR (רשימות פעילות) |
| החזר | `delegation_return_period` = 5 ימים (נמדד על-שרשרת) |
| קיבולת | פרופורציונלי ל-SP; השוק רעב ל-SP שכור |
| סיכונים | צד-שני לא מחזיר דמי-שכירות → **הפחת**: תשלום מראש לתקופה, או חוזה דרך ה-Escrow שלנו (BOT-7 — אכילה לעצמנו) |
| Guardrail | סף שכירות: לא יותר מ-70% מה-SP; מעקב אשראי יומי |

### BOT-2 · Curation — הכנסה מכנית שנייה (P=0.75↑, **APR נמדד חי 3.3–7.6%** + צבירת SP)
> **עדכון גל-2**: ההערכה הישנה (2–4% APY) הוחלפה במדידה חיה של 5 קוראים מקצועיים
> (EXPLORATION_WAVE2.md §1). פרופיל מנצח: **~28 הצבעות/יום במשקל 34%** → 7.2–7.6% APR
> (steemcurator03/04). פזרנות (70–92 הצבעות ב-8–12%) מניבה רק 3.3–6%.
> חוק תקציב VP (מאומת): שריפה יומית ≤ 20% (רג'נרציה); המקצוענים שורפים 12–19.6%.
| פרמטר | ערך |
|---|---|
| תקציב רשת | 32.5% אינפלציה ≈ **$1,226/יום** לכל האוצרים ביחד |
| מכסת הצבעות | HF21: `vote_power_reserve_rate=10` → **~10 הצבעות מלאות/יום**; 25% מהמאגר דאונווט נפרד |
| חלון קריטי | `reverse_auction_seconds=300` — הצבעה ב-5 הדקות הראשונות = הפסד; אופטימום 5–30 דקות |
| אסטרטגיה | שובלי סוסים-גדולים מוותיקים + סינון-תוכן (LLM זול לדירוג איכות) + הימנעות מ-downvote wars |
| Ops/מפתח | `vote` (Posting בלבד!) — הבוט הבטוח ביותר להרצה |
| Guardrail | רשימת-הימנעות (plagiarism/spam), תקרת weight, לוג כל הצבעה |
### BOT-3 · המרת SBD (גל-2: אירועי, מגודר, עם backtest כנה)
> **תיקון כנה מ-backtest** (EXPLORATION_WAVE2.md §4): לאורך 60 יום ה-edge הממוצע ≈ 0
> (חיובי רק 36.7% מהימים) — ה-"+4%" הוא תמונת-רגע. הבוט יורה **רק באירועים**
> (edge ≥ +3% נטו; E[edge|trigger] = +6.19% גולמי נמדד), ומחייב **גידור short STEEM**
> לחלון 3.5 הימים — נמדדו 19 אירועי מינוס-15%+/3 ימים בשנה (מקס −31.5%): לא-מגודר = מחיקה.
| פרמטר | ערך |
|---|---|
| נוסחת טריגר | `edge = market(SBD) − (1/feed_פעיל)×market(STEEM)`; **יורה רק כש-edge ≥ +3%** |
| feed_פעיל | מנוהל-חוב: `9×SBD_supply/STEEM_supply` (זהות נמדדת — ראו T1); רג'ים-תלוי — אסור להקרין K אחורה |
| מחזור | קנה SBD בשוק חוץ → `convert` (Active) → 3.5 ימים → STEEM בערך-$1-feed → מכור **עם short STEEM סימולטני** |
| MC 90 יום | bootstrap מהפיזור הנמדד: חציון **+121%**, p10 +82% (תיאורטי, לפני קיבולת וביצוע) |
| תדירות | טריגר ב-23.3% מהימים (~21 אירועים/90 יום); ההון יושב בהמתנה בין אירועים |
| קיבולת | מלאי SBD כולו ~6.4M; ריאלי **$10–50K** בלי להזיז מחיר |
| Guardrail | לא יותר מ-30% מה-SBD בו-זמנית; עצירה אם feed_פעיל קופץ ±20%; **אין גידור זמין → אין ריצה** |
### BOT-4 · פער בין-מקומי בשוק הפנימי (חדש — מהמדידה; צילום-מצב גל-2)
| פרמטר | ערך |
|---|---|
| מדידה גל-2 | פנימי ask 0.0987 SBD/STEEM ($0.0392) מול חוץ $0.0433 → **הפנימי זול ב-9.35%** (spread ראש-ספר 4.92%; עומק קרוב-לנגיעה ~$1.6K — רדוד) |
| הצלבה | 3 מדידות בלתי-תלויות מאששות: edge המרה +4.13% ∥ דיסקאונט פנימי-מול-convert 5.4% ∥ דיסקאונט פנימי-מול-חוץ 9.35% |
| מסלול | `limit_order_create` קנייה בפנים (Active) → withdraw STEEM לבורסה → מכירה |
| עמלות | 0.75% התאמה פנימית + משיכה ~1% + בורסה ~0.1% → **נטו ~+6%** למחזור (על הפער החדש) |
| קיבולת | עומק רדוד: ריאלי $1–5K למחזור בלי להזיז |
| מחזור | שעות-עד-יום (זמני משיכה) |
| כיוון הפוך | כשהפער מתהפך — מכור SBD בפנים במקום בחוץ |
| Guardrail | פער מינימלי נטו +3%; מחיר סימולטני משני מקורות; עצירה בחוסר-התאמה מקורות |
### BOT-5 · Market Maker פנימי (חדש)
- Spread ראש-ספר נמדד **7.5%** והפער ±2% ריק לגמרי — מרווח ריווח פתוח.
- הצבת שתי הזמנות סביב mid, מחיר-מחדש כל בלוק-משמעותי; סיכון עיקרי: adverse selection
  (סוחרים אוכלים צד אחד לפני תזוזת שוק-חוץ) → פתרון: רוחב דינמי קשור לפער BOT-4.
- Ops: `limit_order_create` + `limit_order_cancel` (Active). הון דו-צדדי; תקרת-מסה 50/50.

### BOT-6 · SPS — כלל מדוד: בלי ~52M SP הצבעות, אין מימון
- מדדנו: Return Proposal = 52–83M SP הצבעות; מעליו רק הצעות של קהילות-על.
- **המסקנה ההנדסית**: SPS הוא וקטור משני שנחסם ע"י פרמטר יחיד מדוד. הדרך היחידה:
  בניית קהילה/שירות קודם (BOT-1/2/7/8) → הצבעות מצטברות → רק אז הצעה.
- Ops: `create_proposal`, `update_proposal_votes` (Active). עלות: 0. P: בתוך המסלול הארוך.

### BOT-7 · בורר Escrow — נישה עם יתרון-ראשון
- זרימה: `escrow_transfer` (מפקיד) → רטיפיקציה עד 3 ימים → `escrow_release`/`escrow_dispute`.
- העמלה נקבעת ב-`escrow_transfer` ומגיעה לבורר בעת השחרור. נפח כרגע זעיר — הערך הוא
  להיות הבורר-האוטומטי הראשון (מוניטין → הצבעות → SPS/עדים). שילוב: שירות-שכירות SP
  שלנו משתמש ב-Escrow שלנו → בעיה-תעשייתית שאנחנו הפתרון שלה.
- Ops: `escrow_approve`, `escrow_release` (Active) — רק בחוזים שאושררו מראש.

### BOT-8 · L2 + תחרויות קהילה (הזרמת תוכן מבוקרת)
- Steem-Engine (custom_json): חקלאות טוקנים/דיבידנדים — פריפריה אך אוטומטית.
- **Steemit Engagement Challenge**: תחרויות שבועיות עם פרסי-הצבעה מהאוצרים הגדולים
  ברשת — נמדד שפעיל לפחות עד Season 18. בוט-סלקטור: זיהוי תחרויות פתוחות, התאמת
  נושאים למומחיות-אמיתית, הגשה בזמן. חצי-אוטומטי (התוכן צריך להיות אמיתי) אבל ה-ROI
  גבוה: קולות @steemcurator01 שווים מאות דולרים לפוסט זוכה.
- Ops: `comment`, `custom_json` (Posting בלבד — אפס סיכון הון).

### BOT-9 · היגיינה (מובנה בכל מודול)
- `claim_reward_balance` יומי, ביטול הזמנות תקועות, מעקב RC (`rc_api.find_rc_accounts`),
  ניקוי delegation שפג. חינם, מונע דליפות.

### BOT-10 · יצירת חשבונות (חדש בגל-2) + `recurring_transfer` כמאפשר
- **נמדד חי**: `account_creation_fee = 3.0 STEEM` (~$0.13) נשרף תמורת `claim_account`;
  מלאי מוכח בשוק: justyy מחזיק 309,632 חשבונות-מוכנים, steemchiller 45,413.
- שני שימושים: (א) מכירת חשבונות/onboarding (שוליים גבוהים, EV קטן, דורש Active);
  (ב) **תשתית פנימית ל-SAOS** — צבא-סוכנים דורש עשרות חשבונות; claim עם SP גדול = התרחבות זולה.
- `recurring_transfer` (HF24) חי ומאומת — מינויים על-שרשרת ללא אמון: חיוב חוזר
  לבוטי-תוכן/שכירות-SP; הופך את מודול mutual-aid (12) לאמיתי.
- Ops: `claim_account` + `create_claimed_account` + `recurring_transfer` (Active).

   BOT-9 היגיינה. מדידת תשואה שבועית מול הסימולציה.
3. **ימים 31–60**: BOT-1 (שכירות SP) על SP שנצבר + BOT-3 pilot על $100–300 SBD.

4. **ימים 61–90**: הכפלת המנצחים; BOT-5 אם תזרים מוכח; פתיחת נוכחות-קהילה (BOT-7/8)
   שמזריקה מוניטין למסלול ארוך-טווח (SPS/עדים).

   (תקדים ההקפאות 2020); תשואה נמדדת בדולרים, לא ב-STEEM.

## 6. מה נשאר לאימות בעת אינטגרציה (רשימה כנה)
1. זהות ה-feed-מנוהל-חוב מול קוד המקור של השרשרת (נמדדה אמפירית, לא הוכחה מהקוד).
2. הרשאת המפתח המדויקת ל-`create_proposal` / `account_witness_vote` (לוודא ב-steem-js).
3. זמני משיכה אמיתיים מהבורסות הפעילות (Binance SBD/BTC מבוטל — נמדד; נותרו Upbit/Bithumb/אחרות לווידוא).
4. עלות RC מדויקת לכל op לחשבון-קטן (מדדנו max_rc לחשבון גדול; נוסחת-עלות לוודא ב-harness).
5. זמינות רשימות השכירות (15–17% APR) בפועל — תמחור דינמי.
